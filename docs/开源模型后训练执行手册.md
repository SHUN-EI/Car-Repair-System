# 开源模型后训练执行手册

> 决策与边界见 [开源模型后训练技术方案](./开源模型后训练技术方案.md)。本文只写能照着跑的步骤：数据从哪张表出来、怎样脱敏成 JSONL、怎样用 LLaMA-Factory 训、怎样用 vLLM 换掉 `DEEPSEEK_BASE_URL`。
>
> 字段和提示词以当前代码为准：`backend/app/models/work_order.py`、`knowledge.py`、`manual_code.py`、`quote.py`、`vehicle.py`、`customer.py`，以及 `answer_generator.py`、`guided_repair_agent.py`、`knowledge_extractor.py`、`core/config.py`。
>
> 训练产物、JSONL、合并权重放门店内网的私有训练目录，不要提交进本仓库。本仓库继续只保留业务代码。

## 0. 这次实际训什么

| 做 | 不做 |
| --- | --- |
| 主路径：Qwen2.5-7B-Instruct 的 QLoRA SFT，任务是引导 JSON、检索问答、车主三段问诊、知识抽取 JSON、拒答 | 不改 `domain/quote_service.py`，价格仍由规则引擎算 |
| 有采纳对之后再做 DPO 或 ORPO | 默认不训、不换 `BAAI/bge-m3`，`MILVUS_VECTOR_SIZE` 保持 1024 |
| 可选：Qwen3-Reranker-0.6B 成对微调，接口仍是 8010 的 `/v1/rerank` | 不把 CPT 和 SFT 写进同一次 `llamafactory-cli train` |

最小硬件：1 张 24GB 卡（3090 / 4090 / A10）跑 7B QLoRA，再在同卡或另一张卡上用 vLLM 推理。只有 16GB 时先不要上 14B。

基座用 `Qwen/Qwen2.5-7B-Instruct`（Apache-2.0，下权重前再核对模型卡）。它和现网 `ChatOpenAI(temperature=0.5)` 的调用方式兼容：推理端只要提供 OpenAI `/v1/chat/completions`。

## 2. 数据怎么准备

监督信号来自已经结案的工单、已发布知识和技师改过的回答。教师模型只用来补「同一上下文下的原稿」，方便和技师终稿组成偏好对。

### 2.1 从结案工单导出

只用 `CLOSED` / `COMPLETED`。`DRAFT`、`QUOTING`、`CANCELLED` 不进训练集。`store_id` 原样写入 `meta`，训练时按店过滤。

`vehicles.plate` / `vin`、`customers.name` / `phone` / `id_no` 不进 JSONL。车型只留 `make`、`model`、`year`。`log_text` 先截断再交给脱敏，和 `knowledge_extractor.py` 一样最多取前 500 字，后面组样本时只留错误码和信号词。

`backend/` 下执行：

```python
"""导出结案工单。放到训练仓 scripts/export_work_orders.py，在 backend/ 下运行。"""
import json
import os
import sys

sys.path.insert(0, os.path.dirname(os.path.dirname(os.path.abspath(__file__))))

from app.core.database import SessionLocal
from app.models.vehicle import Vehicle
from app.models.work_order import WorkOrder, WorkOrderStatus

KEEP = {WorkOrderStatus.CLOSED, WorkOrderStatus.COMPLETED}


def main(out_path: str, store_id: int | None = None) -> None:
    db = SessionLocal()
    try:
        q = db.query(WorkOrder).filter(WorkOrder.status.in_(list(KEEP)))
        if store_id is not None:
            q = q.filter(WorkOrder.store_id == store_id)
        n = 0
        with open(out_path, "w", encoding="utf-8") as f:
            for wo in q.yield_per(200):
                vehicle = db.get(Vehicle, wo.vehicle_id) if wo.vehicle_id else None
                # 只取车型，不取客户姓名、手机、证件、车牌、VIN
                row = {
                    "work_order_id": wo.id,
                    "store_id": wo.store_id,
                    "fault_description": wo.fault_description or "",
                    "fault_phenomenon": wo.fault_phenomenon or "",
                    "fault_code": wo.fault_code or "",
                    "device_error_code": wo.device_error_code or "",
                    "log_text": (wo.log_text or "")[:500],
                    "root_cause": wo.root_cause or "",
                    "solution_steps": wo.solution_steps or "",
                    "repair_result": wo.repair_result or "",
                    "used_parts": wo.used_parts or [],
                    "solution_ref_knowledge_id": wo.solution_ref_knowledge_id,
                    "make": vehicle.make if vehicle else "",
                    "model": vehicle.model if vehicle else "",
                    "year": vehicle.year if vehicle else None,
                    "status": wo.status.value,
                }
                f.write(json.dumps(row, ensure_ascii=False) + "\n")
                n += 1
        print(f"exported {n} -> {out_path}")
    finally:
        db.close()


if __name__ == "__main__":
    main(sys.argv[1] if len(sys.argv) > 1 else "work_orders.jsonl")
```

### 2.2 脱敏

在组 JSONL 之前对每条文本跑一遍。保留品牌、年款、故障码、件号这类维修语义，去掉身份信息。

```python
import re

PLATE = re.compile(r"[京津沪渝冀豫云辽黑湘皖鲁新苏浙赣鄂桂甘晋蒙陕吉闽贵粤青藏川宁琼][A-Z][A-Z0-9]{5,6}")
VIN = re.compile(r"\b[A-HJ-NPR-Z0-9]{17}\b")
PHONE = re.compile(r"1[3-9]\d{9}")
IDNO = re.compile(r"\b\d{17}[\dXx]\b")
HEX_LINE = re.compile(r"(?:0x)?[0-9A-Fa-f]{8,}(?:[\s,]+(?:0x)?[0-9A-Fa-f]{2,}){3,}")

def redact(text: str, names: list[str] | None = None) -> str:
    if not text:
        return ""
    text = PLATE.sub("[车牌]", text)
    text = VIN.sub("[VIN]", text)
    text = PHONE.sub("[手机]", text)
    text = IDNO.sub("[证件]", text)
    text = HEX_LINE.sub("[日志十六进制已删除]", text)
    for name in names or []:
        if name and len(name) >= 2:
            text = text.replace(name, "[客户]")
    return text
```

`names` 用当店 `customers.name` 做词典，导出时按 `customer_id` 查到名字后传入，名字本身不写入样本。脱敏后再人工抽 30 条，确认车牌、手机、客户姓名没有残留。

`log_text` 进 CPT 或 SFT 时只留错误码和信号词，与 `KnowledgeExtractorAgent` 的系统提示一致：日志用来抽 `SV0436` 这类报警码，整段十六进制不进 `content`。

### 2.3 组成 SFT JSONL

一行一条，OpenAI messages 格式，LLaMA-Factory 直接读。顶层必填 `id`、`meta.store_id`、`meta.task`、`messages`。`meta.task` 用来配比，不要混成一个没有标签的大文件再指望脚本猜。

系统提示直接贴现网字符串，避免训出来的格式和 `guided_repair_agent.py` / `answer_generator.py` 对不上：

| meta.task | 系统提示来源 | assistant 必须满足 |
| --- | --- | --- |
| `guided_json` | `GuidedRepairAgent.SYSTEM_PROMPT` | `json.loads` 后有 `message`、`options`、`status` |
| `consult_chat` | `GuidedRepairAgent.CONSULT_CHAT_SYSTEM_PROMPT` | 含【症状】【建议项目】【是否预约】 |
| `rag_answer` | `AnswerGenerator.SYSTEM_PROMPT` | 只复述检索案例；无匹配时写未检索到 |
| `extract_kb` | `knowledge_extractor.py` 里的提取系统提示 | JSON：`title/content/fault_code/device_type/fault_tags/keywords` |
| `refuse` | 同上问答或引导提示 | 与 `REPAIR_IRRELEVANT_REPLY` 同义：先说明与维修无关，再给故障描述例子 |

引导 JSON 正例用同一条到店闭环：2018 大众速腾 1.4T 读到 P0300。检索上下文按现网截断到 600 字，见 `guided_repair_agent.achat` 里 `content[:600]`。完整问诊、抽取、拒答行见 [技术方案的到店闭环](./开源模型后训练技术方案.md)。

```json
{
  "id": "sft-guided-p0300-1",
  "meta": {"store_id": 1, "task": "guided_json", "work_order_id": 1203, "synthetic": false},
  "messages": [
    {"role": "system", "content": "<GuidedRepairAgent.SYSTEM_PROMPT 原文>"},
    {"role": "user", "content": "故障现象：2018 大众速腾 1.4T，热车怠速抖动，故障灯偶发，读到 P0300。\n\n【参考案例1】汽修样例 OBD 手册 · P0300 多缸随机失火\n处理要点：读取失火计数，检查点火线圈和火花塞，再检查进气泄漏。"},
    {"role": "assistant", "content": "{\"message\":\"热车怠速抖动且读到 P0300，先按手册核对失火计数和点火侧。\",\"options\":[{\"id\":\"A\",\"cause\":\"点火线圈、火花塞或混合气异常导致随机失火\",\"diagnostic_action\":\"读取失火计数，检查点火线圈和火花塞，再检查进气泄漏\"}],\"status\":\"awaiting_action\"}"}
  ]
}
```

`assistant.content` 用 `json.dumps(..., ensure_ascii=False)` 生成，训练前用下面的校验确认能 `json.loads`。`options` 最多 3 条，和系统提示里的「每步 2-3 个方向」一致。

知识抽取的 user 文本对齐 `_invoke_extraction` 的模板：设备类型、故障码、故障描述、故障现象、根本原因、解决方案、日志前 500 字、标签。assistant 是抽取 JSON，`content` 里用「故障现象 / 原因分析 / 排查步骤 / 处理方法 / 预防措施」五段，不粘贴日志原文。

拒答负例的 user 用闲聊（「今天天气怎么样」「帮我查工资」），assistant 用 `retrieval_flow.REPAIR_IRRELEVANT_REPLY` 的原文。这类样本大约占 10%，否则模型会把闲聊答成维修步骤。

检索案例不够时的正例也要有：user 里写「未检索到匹配案例」，assistant 写知识库未覆盖、建议到店或联系资深工程师。这段话术在 `CONSULT_CHAT_SYSTEM_PROMPT` 和 `CHAT_SYSTEM_PROMPT` 里已经写死，SFT 要让模型跟着说，而不是用通用经验补零件名。

配比按条数抽样，某一桶还没数据就先空着，不要用合成数据把比例凑满：

| task | 占比 |
| --- | --- |
| guided_json | 30% |
| rag_answer | 25% |
| consult_chat | 15% |
| extract_kb | 15% |
| refuse | 10% |
| 工具叙述（怎样说明要查知识库或走报价草案，不生成单价） | 5% |

组文件：

```python
import json, random
from collections import defaultdict

RATIO = {
    "guided_json": 0.30,
    "rag_answer": 0.25,
    "consult_chat": 0.15,
    "extract_kb": 0.15,
    "refuse": 0.10,
    "tool_narration": 0.05,
}

def build(rows: list[dict], n: int, seed: int = 7) -> list[dict]:
    random.seed(seed)
    by = defaultdict(list)
    for r in rows:
        by[r["meta"]["task"]].append(r)
    out = []
    for task, ratio in RATIO.items():
        bucket = by.get(task) or []
        if not bucket:
            print(f"skip empty bucket: {task}")
            continue
        need = int(n * ratio)
        out.extend(random.choices(bucket, k=need) if len(bucket) < need else random.sample(bucket, need))
    random.shuffle(out)
    return out
```

划分按工单，不按单条消息：同一 `work_order_id` 的多轮全部进 train 或全部进 valid。`zlib.adler32(work_order_id) % 10 == 0` 的工单进 valid，其余进 train。对外发布的 adapter 只用合同允许的店；`meta.store_id is None` 只留给公开手册，门店案例必须带店号。两个文件分别登记成 `car_repair_sft` 和 `car_repair_sft_valid`。

### 2.4 偏好对（阶段 C 才需要）

样本少于约 500 对时先不做 DPO，把 SFT 训完上线观察。够了再用技师终稿做 chosen、模型原稿做 rejected。

报价行可以进偏好，但只比较「项目名称和数量是否被技师保留」。`quote_lines.unit_price` / `amount` 不作为生成目标。`quotes.status` 到 `STAFF_CONFIRMED` 或 `CUSTOMER_CONFIRMED` 的行是 chosen；被删掉或改名的草案叙述是 rejected。

LLaMA-Factory 的偏好数据用 sharegpt 排序格式：`conversations` 是提示，`chosen` / `rejected` 各是一条 gpt 回复。

```json
{
  "id": "dpo-quote-brake-88",
  "meta": {"store_id": 1, "task": "quote_lines_pref"},
  "conversations": [
    {"from": "system", "value": "只复述技师确认留下的项目名称，不写单价。"},
    {"from": "human", "value": "问诊建议：检查刹车盘厚度与刹车片剩余量；盘面起槽或片磨到限位时更换刹车盘/片。技师确认时只保留检查，删除更换。"}
  ],
  "chosen": {"from": "gpt", "value": "确认项目：检查刹车盘厚度与刹车片剩余量。"},
  "rejected": {"from": "gpt", "value": "确认项目：检查刹车盘片，并更换刹车盘/片，合计 1280 元。"}
}
```

rejected 里故意带了单价，用来压「模型自己报价」这个失败模式。单价的真值仍以 `create_draft` 为准。

### 2.6 可选：CPT 纯文本

一行一个 `text` 字段。来源是已发布知识正文、手册 `description` + `conditions`、脱敏后的结案方案。门店私有案例带 `store_id`，公开手册置空。目标先攒 5 万到 50 万 tokens，用基座 tokenizer 数：

### 2.7 写出前的质检

```python
import json

def check(path: str) -> None:
    n = leaks = bad_json = 0
    for line in open(path, encoding="utf-8"):
        n += 1
        row = json.loads(line)
        blob = json.dumps(row, ensure_ascii=False)
        if any(s in blob for s in ("[车牌]", "[VIN]", "[手机]", "[证件]")):
            pass  # 占位符可以留下
        # 脱敏没拦住时，原始模式不应再出现；这里只查占位符以外的明显手机号
        import re
        if re.search(r"1[3-9]\d{9}", blob):
            leaks += 1
        if row.get("meta", {}).get("task") == "guided_json":
            content = row["messages"][-1]["content"]
            try:
                data = json.loads(content)
                assert "message" in data and "status" in data and "options" in data
            except Exception:
                bad_json += 1
    print({"rows": n, "phone_leaks": leaks, "bad_guided_json": bad_json})
```

`phone_leaks` 和 `bad_guided_json` 都要是 0 再开训。同时打印各 `meta.task` 条数和各 `store_id` 条数，确认没有把别的店混进这一份训练集。

## 4. 冻结评测包，再填分数

评测包在开训前抽好，之后不增删。建议规模：引导 JSON ≥ 50，检索问答 ≥ 50，拒答 ≥ 30，车主三段 ≥ 30。每条带 `store_id`，输入里的检索案例用当时的 top 案例快照，避免评测时检索漂移把模型分算脏。

基线是现网 `DEEPSEEK_BASE_URL` + `DEEPSEEK_MODEL`，检索仍是 bge-m3 和当前阈值。本地模型和基线打同一份包。

```python
"""对 OpenAI 兼容端口跑冻结包。temperature 与现网 ChatOpenAI 一致，取 0.5。"""
import json
from openai import OpenAI

client = OpenAI(base_url="http://127.0.0.1:8001/v1", api_key="dummy")

def run(pack_path: str, model: str) -> None:
    ok = n = 0
    for line in open(pack_path, encoding="utf-8"):
        row = json.loads(line)
        n += 1
        resp = client.chat.completions.create(
            model=model,
            temperature=0.5,
            messages=row["messages"][:-1],  # 去掉金标 assistant
        )
        text = resp.choices[0].message.content or ""
        if row["meta"]["task"] == "guided_json":
            try:
                data = json.loads(text.strip().removeprefix("```json").removesuffix("```").strip())
                ok += int({"message", "options", "status"} <= set(data))
            except json.JSONDecodeError:
                pass
        elif row["meta"]["task"] == "consult_chat":
            ok += int(all(s in text for s in ("【症状】", "【建议项目】", "【是否预约】")))
        elif row["meta"]["task"] == "refuse":
            ok += int("和设备维修无关" in text or "与维修无关" in text)
    print(model, ok, "/", n)
```

通过线沿用技术方案里的门禁：引导 JSON 合法率绝对 ≥ 95%，且不低于基线 1 个百分点；拒答不低于现网阀门加模型的组合；车主三段结构不低于基线。领域回归仍跑：

```bash
cd backend && python -m pytest tests/test_phase0_domain.py tests/test_phase1_loop.py tests/test_phase2_commerce.py tests/test_auth_scope.py -q
```

`test_phase1_loop.py` 会检查 `CONSULT_SYSTEM_PROMPT` 里仍有「症状理解 / 建议项目 / 是否预约」。这些单测保证业务文案没被改掉，不代替上面的冻结包。
