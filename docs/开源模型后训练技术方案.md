# 汽修项目开源模型后训练技术方案

> 本文按仓库代码落仓，不把 Canvas 源文件放进仓库。配置名和路径以 `backend/app/core/config.py` 为准：召回是 `BAAI/bge-m3`，`MILVUS_VECTOR_SIZE=1024`，精排是 `BAAI/bge-reranker-v2-m3`，Chat 仍走 `DEEPSEEK_BASE_URL` / `DEEPSEEK_MODEL`（代码默认 `deepseek-chat`，`.env.example` 示例 `deepseek-v4-flash`）。
>
> 相关文档：[开源模型后训练执行手册](./开源模型后训练执行手册.md)（数据导出、JSONL、训练命令与接回步骤）、[代码完善清单](./代码完善清单.md)、[汽修 Agent 平台改造方案](./汽修-Agent-平台改造方案.md)、[docs 目录说明](./README.md)。
>
> 阈值脚本已支持 `--profile industrial|auto|all`。仓库仍没有 LLM 自动打分 harness；鉴权回归在 `backend/tests/test_auth_scope.py`。

> 优先后训练 Chat LLM（问诊/引导/JSON 输出），可选微调 Reranker；默认不换 bge-m3；训完用 OpenAI 兼容本地服务替换 `DEEPSEEK_BASE_URL` 灰度回现网。
>
> 依据仓 https://github.com/SHUN-EI/Car-Repair-System 代码事实（不以过时 README 为准）：`backend/app/core/config.py`、`embedding_server.py`、`guided_repair_agent.py`、`answer_generator.py`、`scripts/calibrate_thresholds.py`。

## 一句话决策

Chat LLM 是后训练主战场；Reranker 可做领域偏好微调；Embedding（bge-m3 / 1024 维）默认冻结，换模型必须重建 Milvus 集合并重跑 `calibrate_thresholds.py`，禁止未重建索引就改维度。

**「冻结 bge-m3」= 继续用现网** `bge-m3` **做向量化，不做后训练、也不换模型。** 不是「不用 bge-m3」。

## 目标与边界

目标：用开源模型把「门店汽修 Agent」从依赖云端 DeepSeek，推进到可离线/半离线的同协议本地 Chat 服务，同时保持现有 LangGraph/检索工具协议、门店隔离与报价规则引擎不变。

边界：本方案不改业务状态机，不重写 Vue 前端；报价草案 `create_draft` 仍走规则域（`domain/quote_service.py`），后训练不替代定价规则。不做全国多租户训练平台。训练样本必须按 `store_id` 隔离并脱敏。

| 项 | 说明 |
| --- | --- |
| 主训对象 | Chat LLM（问诊 SSE / 引导 JSON / 知识抽取 JSON） |
| 次训对象 | Qwen3-Reranker-0.6B（可选，成对相关性） |
| 默认冻结 | BAAI/bge-m3 + Milvus IVF_FLAT 1024 维 |
| 接回方式 | 改 `DEEPSEEK_BASE_URL` / `DEEPSEEK_MODEL`，保持 ChatOpenAI |
| 验收基线 | 现网 DeepSeek + bge-m3 + 现阈值 |

## 现网模型锚点（代码事实）

| 组件 | 配置/端口 | 代码位置 | 备注 |
| --- | --- | --- | --- |
| Embedding | `BAAI/bge-m3`；`EMBEDDING_SERVER_URL=http://localhost:8010`；dim=`MILVUS_VECTOR_SIZE=1024` | `core/config.py`、`core/embeddings.py`、`core/embedding_server.py` | `/v1/embeddings`；L2 归一化 dense |
| Reranker | `BAAI/bge-reranker-v2-m3`；同机 `/v1/rerank`（分数 0~1）；`RERANKER_CANDIDATES=30` | `core/reranker.py`、`embedding_server.py` | 失败冷却 60s，回退规则重排 |
| Chat LLM | `DEEPSEEK_API_KEY` + `DEEPSEEK_BASE_URL` + `DEEPSEEK_MODEL`；`.env.example` 示例 `deepseek-v4-flash`，`config.py` 默认 `deepseek-chat` | `answer_generator.py`、`guided_repair_agent.py`、`expert_repair_agent.py`、`knowledge_extractor.py`、`robot_graph.py` 等 | 统一 `langchain_openai.ChatOpenAI` |
| 检索阈值 | 粗筛 `RETRIEVAL_COARSE_THRESHOLD=0.45`；语义兜底 0.6；单路 0.3；去重 0.45/0.55；Agent 质量 0.6/0.7 | `core/config.py`、`scripts/calibrate_thresholds.py` | 换 embedding 必须重标定 |
| 报价 | `POST /quotes/draft` → `domain.quote_service.create_draft`；MCP `draft_quote` | `api/quotes.py`、`mcp/tools.py` | 规则组装，非 LLM 生成价格 |
| 问诊/引导 | `guided_repair_chat` SSE；结构化追踪 JSON options；车主 `CONSULT_CHAT_SYSTEM_PROMPT` | `api/search.py`、`guided_repair_agent.py` | 严格 JSON / 三段问诊结构可当监督信号 |

评测现状：仓库现有 pytest（`test_phase0~3`、`test_extract_error_codes`）覆盖领域状态机/预约槽/意图阀门文案，没有现成 LLM 自动打分 harness。指标数值写「待补充」，先建冻结评测包再填。

## 训什么、不训什么

```
Chat LLM（主训：SFT→偏好对齐）──主路径──► vLLM OpenAI API（替换 DEEPSEEK_*）
Reranker（可选：成对偏好/对比）──虚线──► 独立服务或同机
bge-m3（默认冻结）──仅当全量重索引──► 同上
报价/fitment/库存规则（不训，继续代码域）──协议保持──► 同上
```

| 对象 | 建议 | 理由 | 接回成本 |
| --- | --- | --- | --- |
| Chat LLM | 必须训 | 现网所有生成/问诊/JSON 引导都走 DeepSeek 兼容口；本地替换收益最大 | 低：改 BASE_URL/MODEL |
| Reranker | 优先可选 | 汽修术语/车型件号排序敏感；维度不变，不必重建向量库 | 中：替换 8010 内 rerank 权重或独立 `/v1/rerank` |
| Embedding | 慎训 / 慎换 | 集合 `knowledge`/`log_code` 绑死 1024 维与分数分布；换模型=全量 `sync_vectors` + 阈值重标定 | 高 |
| 报价引擎 | 不训 | `create_draft`/`rank_offers` 是确定性规则；可用 SFT 学如何组织 consult_text/建议项，不学造价格 | — |

硬约束：不要「先换个更好的 embedding 试试」而未重建索引。若必须做领域 embedding，单独开里程碑：新集合名（如 `knowledge_v2`）→ 双写对比 → 重跑 `calibrate_thresholds.py` → 再切 `MILVUS_COLLECTION`。

## 基座选型与方法对比

| 基座 | 许可注意 | 显存档（QLoRA 约） | 适配本项目理由 | 不选它的情况 |
| --- | --- | --- | --- | --- |
| Qwen2.5-Instruct 7B | Apache-2.0（权重按卡确认） | 单卡 24GB 可训可推 | 中文指令强、工具/JSON 稳；门店单卡最小可行 | 长上下文多手册拼接不够时升级 14B |
| Qwen2.5/Qwen3-Instruct 14B | 按卡确认 | 24GB QLoRA 可训；推荐 48GB 或双卡舒适推 | 多轮引导+手册情形清单更稳 | 只有一张 16GB 卡时 |
| DeepSeek-R1-Distill-Qwen-7B/14B | 按卡确认 | 同档 | 与现网 DeepSeek 风格接近，迁移话术成本低 | 需要更强「拒答/只依据检索」约束时优先原版 Instruct + 强 SFT |
| 继续用云 DeepSeek | 商业 API | 0 本地显存 | 作对照基线与教师模型合成数据 | 整机离线门店 |

| 方法 | 对本项目用途 | 数据形态 | 阶段 | 注意 |
| --- | --- | --- | --- | --- |
| Domain CPT（继续预训练） | 可选：灌手册/SOP/故障码散文，降低术语生僻度 | 纯文本包（去隐私） | 阶段 A | 与 SFT 分开；学习率更小；过拟合会背诵件号 |
| SFT | 主路径：问诊结构、引导 JSON、知识抽取 JSON、拒答与引用规范 | messages JSONL + 可选 tools | 阶段 B | 必须含负例与「知识库未覆盖」 |
| DPO / ORPO | 技师采纳 vs 改写；车主问诊被点「有用」vs 被纠正 | chosen/rejected 对 | 阶段 C | 样本少时用 ORPO；严禁跨店混偏好 |
| 对比学习 / 成对 CE | Reranker 领域微调 | (query, pos, neg) | 并行可选 | 负例用错车型/错件号/无关手册 |
| 全参微调 Embedding | 默认不做 | — | 独立里程碑 | 必须新集合+阈值重标定 |

## 数据工程

监督信号优先来自已发生的业务闭环，而不是凭空合成万能答案。下面用门店里真实会走到的一条闭环说明每类样本长什么样。知识正文取自 `backend/app/domain/auto_repair_seed.py` 已发布样例，报价价格仍由 `quote_lines.py` / `create_draft` 从目录取值。

### 一条到店闭环

门店 `store_id=1`。车辆是 2018 款大众速腾 1.4T，里程约 6 万公里。样本里保留品牌、车系、年款、排量、故障码；车牌、VIN、手机、客户姓名在导出时替换掉。

车主在问诊里说：「踩刹车有金属摩擦声，低速点刹更尖。」检索命中已发布知识「【汽修样例】刹车异响与刹车盘片检查」。接车后技师又读到 P0300，热车怠速抖动。结案工单把这次处理写成知识；报价草案里的项目名称来自问诊「建议项目」，单价来自配件目录，技师确认时删掉了模型多写的施工项。

| 环节 | 业务里发生的事 | 变成哪条训练样本 |
| --- | --- | --- |
| 车主问诊 | `scene=consult`，系统提示 `CONSULT_CHAT_SYSTEM_PROMPT`，回复固定【症状】【建议项目】【是否预约】 | SFT `consult_chat` |
| 技师排查 P0300 | `GuidedRepairAgent.SYSTEM_PROMPT`，每步 2～3 个选项，只引用手册情形 | SFT `guided_json` |
| 结案沉淀 | 工单 `CLOSED`，字段进 `KnowledgeExtractorAgent` | SFT `extract_kb`；可选 CPT 纯文本 |
| 报价确认 | `parse_consult_items` 抽出建议项目，`create_draft` 定价；技师改行后状态到 `STAFF_CONFIRMED` | DPO `quote_lines_pref`，只比较项目名称 |
| 检索排序 | 问句「速腾 刹车金属摩擦声」应排在刹车样例前，而不是 P0420 催化器条目 | Reranker `(query, positive, negative)` |
| 闲聊 | 「帮我查这个月工资」被 `repair_intent_fast_check` 判为无关 | SFT `refuse`，回复用 `REPAIR_IRRELEVANT_REPLY` |

脱敏前后各留一句，训练只吃右边：

```text
原文：车主张伟 13812348000 京A12345 打电话说 2018 大众速腾 1.4T 踩刹车有金属摩擦声
样本：车主[客户] [手机] [车牌] 打电话说 2018 大众速腾 1.4T 踩刹车有金属摩擦声
```

#### 车主问诊（consult_chat）

检索案例截断到 600 字，和 `guided_repair_agent.achat` 一致。assistant 只能复述案例里写明的检查项。案例写的是「盘面起槽或片磨到限位时更换」，不能写成「已经要换盘换片」，也不能报一个目录里才有的价格。

```json
{
  "id": "sft-consult-brake-1",
  "meta": {"store_id": 1, "task": "consult_chat", "synthetic": false},
  "messages": [
    {"role": "system", "content": "<GuidedRepairAgent.CONSULT_CHAT_SYSTEM_PROMPT 原文>"},
    {"role": "user", "content": "车主描述：2018 大众速腾 1.4T，踩刹车有金属摩擦声，低速点刹更尖。\n\n【参考案例1】【汽修样例】刹车异响与刹车盘片检查\n处理要点：症状：踩刹车时有金属摩擦声，或低速点刹出现尖锐异响，制动踏板行程变长。建议项目：检查刹车盘厚度与刹车片剩余量；盘面起槽或片磨到限位时更换刹车盘/片，并清洁导向销。是否到店：制动异响涉及行车安全，建议预约到店。"},
    {"role": "assistant", "content": "【症状】踩刹车有金属摩擦声，低速点刹更明显，和案例中的刹车异响一致。\n【建议项目】检查刹车盘厚度与刹车片剩余量；盘面起槽或片磨到限位时更换刹车盘/片，并清洁导向销。\n【是否预约】制动异响涉及行车安全，建议预约到店。"}
  ]
}
```

同一条链路还要有「知识库没覆盖」的正例。车主改问天窗异响，检索为空时，【建议项目】写「知识库未给出可执行项目」。`parse_consult_items` 看到这句会跳过，不会把空建议写进报价。

#### 技师引导（guided_json）

车已经在店里。手册样例 `P0300` 的情形是：信号「怠速抖动且故障灯闪烁」，原因「点火线圈、火花塞或混合气异常」，步骤「读取失火计数，检查点火线圈和火花塞，再检查进气泄漏」。选项停在这一步，不把更换火花塞写成已经确认的维修。

```json
  "meta": {"store_id": 1, "task": "guided_json", "work_order_id": 1203, "synthetic": false},
  "messages": [
    {"role": "system", "content": "<GuidedRepairAgent.SYSTEM_PROMPT 原文>"},
    {"role": "user", "content": "故障现象：2018 大众速腾 1.4T，热车怠速抖动，故障灯偶发，读到 P0300。\n\n【参考案例1】汽修样例 OBD 手册 · P0300 多缸随机失火\n处理要点：怠速抖动且故障灯闪烁。读取失火计数，检查点火线圈和火花塞，再检查进气泄漏。"},
```

#### 结案抽取（extract_kb）

工单结案后根因已经写明：火花塞间隙过大，线圈测量正常，更换火花塞后怠速恢复。抽取 JSON 的 `content` 用知识提取提示里的五段，`log_text` 只留 `P0300`，不把诊断仪十六进制原文贴进去。

```json
{
  "id": "sft-extract-1203",
  "meta": {"store_id": 1, "task": "extract_kb", "work_order_id": 1203, "synthetic": false},
  "messages": [
    {"role": "system", "content": "<KnowledgeExtractorAgent 提取系统提示原文>"},
    {"role": "user", "content": "设备类型：乘用车\n故障码：P0300\n故障描述：2018 大众速腾 1.4T 热车怠速抖动，故障灯偶发\n故障现象：怠速转速上下波动，车身抖动\n根本原因：火花塞间隙过大，点火线圈正常\n解决方案：更换火花塞，清除故障码，怠速恢复\n设备日志原文：P0300 Random/Multiple Cylinder Misfire Detected"},
    {"role": "assistant", "content": "{\"title\":\"【乘用车】热车怠速抖动 - 更换火花塞\",\"content\":\"## 故障现象\\n2018 大众速腾 1.4T 热车怠速抖动，故障灯偶发。\\n\\n## 原因分析\\n火花塞间隙过大，点火线圈测量正常。\\n\\n## 排查步骤\\n1. 读取 P0300 与失火计数\\n2. 检查点火线圈\\n3. 检查火花塞间隙\\n\\n## 处理方法\\n1. 更换火花塞\\n2. 清除故障码\\n\\n## 预防措施\\n案例未写保养间隔，不补充厂家里程。\",\"fault_code\":\"P0300\",\"device_type\":\"乘用车\",\"fault_tags\":[\"怠速抖动\",\"P0300\",\"火花塞\"],\"keywords\":[\"速腾\",\"怠速抖动\",\"P0300\",\"火花塞\"]}"}
```

```json

```

#### 报价偏好（quote_lines_pref）

问诊【建议项目】被 `parse_consult_items` 收成报价行。目录里「检查刹车盘片」有工时价，「更换刹车盘/片」是另一行，只有检测确认起槽或磨到限位才保留。模型原稿把更换行和合计金额一起说成已确认；技师删掉更换行，只留检查。chosen 用技师留下的项目名，rejected 用原稿。两边都不把 `unit_price` 当生成目标。

```json
{
  "id": "dpo-quote-brake-88",
  "meta": {"store_id": 1, "task": "quote_lines_pref"},
  "conversations": [
    {"from": "system", "value": "只复述技师确认留下的项目名称，不写单价。"},
    {"from": "human", "value": "问诊建议：检查刹车盘厚度与刹车片剩余量；盘面起槽或片磨到限位时更换刹车盘/片。技师确认时只保留检查，删除更换。"}
  ],
  "chosen": {"from": "gpt", "value": "确认项目：检查刹车盘厚度与刹车片剩余量。"},
  "rejected": {"from": "gpt", "value": "确认项目：检查刹车盘片，并更换刹车盘/片，合计 1280 元。"}
}
```

适配负例进 Reranker，不进报价生成。备件 fitment 写的是 `brand=大众, series=速腾, year_from=2016, year_to=2020, engine=1.4T`。问句「2018 大众速腾 1.4T 刹车片」的正样本是这条刹车知识；负样本用库里已有、但和这次症状不是同一系统的条目，例如 P0420 催化器效率，或只适配其他车系的刹车片说明。

```json
{"query": "2018 大众速腾 1.4T 踩刹车金属摩擦声", "positive": "【汽修样例】刹车异响与刹车盘片检查：检查刹车盘厚度与刹车片剩余量", "negative": "P0420 催化器效率低于阈值：对比上下游氧传感器波形", "meta": {"store_id": 1}}
```

#### 拒答

「帮我查这个月工资」走闲聊阀门。assistant 用现网原文：先说明和设备维修无关，再给出故障描述例子（注塑机、空压机、CNC 那句是代码里的 `REPAIR_IRRELEVANT_REPLY`，训练照抄，避免模型改口去答工资）。

```json
{
  "id": "sft-refuse-salary-1",
  "meta": {"store_id": 1, "task": "refuse", "synthetic": true},
  "messages": [
    {"role": "system", "content": "<问答或引导系统提示原文>"},
    {"role": "user", "content": "帮我查这个月工资"},
    {"role": "assistant", "content": "这条消息和设备维修无关，我先不继续处理。\n如果是设备故障，请描述具体的设备和故障现象，例如：\n注塑机温度过高、空压机不启动、CNC 主轴 SV0436 报警。"}
  ]
}
```

| 数据源 | 表/路径 | 可当什么监督 | 脱敏要点 |
| --- | --- | --- | --- |
| 结案工单 | `work_orders`：fault_description / fault_phenomenon / root_cause / solution_steps / used_parts / log_text / status=CLOSED\|COMPLETED / store_id | 诊断 SFT；知识抽取输入；CPT 语料 | 去车牌/VIN/手机/客户名；store_id 写入样本 meta，训练按店分片 |
| 知识条目 | `knowledge_items`（PUBLISHED）+ Milvus `knowledge` | RAG 回答 SFT 的检索案例侧；抽取目标 JSON | 审核通过稿优先；草稿不进训练 |
| 手册/故障码 | `manual_code_entries`、fault_code 映射；集合 `log_code` | CPT；引导步骤正例；rerank 正样本 | OEM 版权语料只做内部训练，不外发 |
| 问诊/引导会话 | Redis `guided_repair_session:*`（TTL 24h）+ 追踪后端（TRACING_BACKEND：ragflow/langfuse/local） | 多轮 SFT；JSON options 格式；车主三段结构 | 待补充：需落库导出流水，勿只依赖 TTL 会话 |
| 报价采纳 | `quotes`/`quote_lines`：草案→确认/改行；工单 used_parts | DPO：系统建议行 vs 技师最终行；不把单价当可生成标签乱训 | 金额可保留相对结构，客户标识剥离 |
| 负例 | 错件号、错车型 fitment、故意不相关手册段、闲聊触发 REPAIR_IRRELEVANT_REPLY | 拒答 SFT；rerank 负样本；意图阀门回归 | 合成时标注 synthetic=true |

### 采集办法（缺指标时先做这个）

1. **落库会话与采纳事件**：在 guided_repair/search SSE 结束时写 PG 表（建议新建 `training_events`：store_id、role、prompt、completion、retrieval_ids、user_action）。现网 Redis TTL 不够当训练集。待补充：表结构 PR。
2. **从结案工单批量导出**：SQL 过滤 store_id + 状态 CLOSED/COMPLETED；跑现有 knowledge_extractor 得 JSON 目标，人工抽检后进 SFT。
3. **教师模型蒸馏**：用现网 DeepSeek 对同一批检索上下文生成答案，技师只标「采纳/改写」→ 自然得到 DPO 对。
4. **负例工厂**：从 fitment 不匹配的备件、跨设备手册、`repair_intent_fast_check` 应拦截的闲聊模板生成 rejected。

### JSONL Schema（可直接喂 LLaMA-Factory）

Chat SFT 用 OpenAI messages 风格一行一条。必填顶层字段：`id`、`meta.store_id`、`meta.task`、`messages[]`；assistant 对引导任务必须是可解析 JSON（message / options / status）。

| 字段 | 示例值 | 说明 |
| --- | --- | --- |
| id | sft-guided-p0300-1 | 样本主键，对应上面 P0300 引导 |
| meta.store_id | 1 | 速腾这条工单所属门店；公开 OBD 手册可 null |
| meta.task | guided_json | 同一次到店的其他桶：consult_chat / extract_kb / refuse |
| messages[0].role | system | 贴现网 SYSTEM_PROMPT / CONSULT / 抽取提示 |
| messages[1].role | user | 「2018 大众速腾 1.4T，热车怠速抖动，读到 P0300」加截断后的手册情形 |
| messages[2].role | assistant | 可解析 JSON：message / options / status=awaiting_action |

上面「一条到店闭环」里的 JSON 就是可直接落入 JSONL 的行。DPO 用其中的报价确认对：chosen 只留「检查刹车盘厚度与刹车片剩余量」，rejected 是把更换行和合计金额说成已确认的原稿。Reranker 用刹车问句对刹车样例为正、对 P0420 为负。CPT 用结案纯文本，公开手册的 `meta.store_id` 置空，这家店的结案方案必须带 1。

### 脱敏与门店隔离规则

- store_id 写入每条样本 meta；训练 DataLoader 禁止无过滤的全库 shuffle；对外输出模型时按合同决定是否只含本连锁数据
- 正则/词典剥离：车牌、VIN、手机、身份证、详细地址、客户姓名；保留车型品牌/年款/故障码
- log_text 只抽错误码与信号词进训练（与 knowledge_extractor 规则一致），禁止整段十六进制日志进 CPT
- 导出物放门店内网对象存储；训练机出网关闭或仅镜像源

## 三阶段训练路线

继续预训练与 SFT/偏好对齐必须分开跑、分开存 checkpoint，禁止 CPT+SFT 一把梭导致指令跟随塌陷。

### 阶段 A — Domain CPT（可选）

1. 语料打包：PUBLISHED 知识 + 手册结构化正文 + 脱敏结案方案；目标 5 万~50 万 tokens 起（待补充：库真实 token 量，用脚本 wc/tokenizer 统计）。
2. 训练：LLaMA-Factory template: qwen，stage: pt，lr≈1e-5，epoch 1~2，seq 2048/4096，保存 `cpt-qwen25-7b`。
3. 门禁：通用指令集抽测不崩；困惑度相对基座下降；禁止背出训练集里的真实车牌（用探针集）。

### 阶段 B — SFT（主路径）

任务配比建议（可按样本数再调；无数据的桶先空着并采集）：引导 JSON 30%（如 P0300 只给到读失火计数这一步）；检索问答 25%（刹车问句只复述盘片检查）；车主问诊三段 15%；知识抽取 JSON 15%（结案火花塞工单）；拒答/闲聊 10%（查工资）；工具叙述 5%（说明建议项目会进报价草案，价格由目录计算）。

LoRA 超参起点（7B QLoRA，单卡 24GB）：

| 项 | 值 |
| --- | --- |
| quantization | bnb qlora 4bit |
| lora_rank | 16（JSON 不稳再试 32） |
| lora_alpha | 32 |
| lora_dropout | 0.05 |
| target_modules | q_proj,k_proj,v_proj,o_proj,gate_proj,up_proj,down_proj |
| lr | 2e-4 |
| batch | 微批 2 × grad_accum 8 |
| epochs | 2~3，早停看 valid JSON 解析率 |
| max_len | 4096（含检索案例截断，对齐现网 content 截断习惯） |

命令骨架：

```bash
CUDA_VISIBLE_DEVICES=0 llamafactory-cli train examples/train_qlora/qwen25_7b_sft_car.yaml
```

YAML 关键字段：`model_name_or_path` 指向 Qwen2.5-7B-Instruct（或阶段 A 的 CPT 合并权重）；`adapter_name_or_path` 为空；`stage=sft`；`do_train=true`；`finetuning_type=lora`；`dataset=car_repair_sft`；`template=qwen`；`output_dir=saves/car-sft-7b`；`quantization_bit=4`。

Unsloth 等价路径（更快原型）：`FastLanguageModel.from_pretrained(..., load_in_4bit=True)` → `get_peft_model` → `SFTTrainer`；导出仍用 HF / merged 16bit 供 vLLM。

### 阶段 C — DPO/ORPO（采纳偏好）

1. 构造偏好对：chosen=技师最终采纳话术/改后报价叙述（刹车例里只留检查盘片）；rejected=模型原稿或被驳回知识（把「条件更换」说成已更换并写出合计）。样本不足 500 对时用 ORPO 或仅做小学习率 DPO 1 epoch。
2. 训练：`stage=dpo`，从 SFT adapter 继续；lr≈5e-6~1e-5；beta≈0.1。
3. 门禁：同题对比 SFT：JSON 合法率不下降；「只依据检索」违规率不升；门店私有实体探针不泄漏。

### Reranker 并行（可选）

冻结 embedding；用 FlagEmbedding / transformers 对 Qwen3-Reranker-0.6B 做成对 CE 或 Listwise。导出后替换 embedding_server 内权重路径（`_RERANKER_LOCAL_CANDIDATES`），接口 `/v1/rerank` 不变。验收：固定 query 集上 nDCG@10 / MRR 相对原版提升（待补充：标注集规模）。

## 评测与上线

基线固定为：现网 `DEEPSEEK_*` + bge-m3 + 当前阈值。本地模型必须在同一批「冻结评测包」上对比；数值列待补充（先建包再填）。

| 门禁项 | 定义方式 | 通过线（相对基线） | 现状 |
| --- | --- | --- | --- |
| 引导 JSON 合法率 | 解析 options/status 字段成功占比。P0300 题的 options 须含「读取失火计数」 | ≥ 基线 - 1pp，且绝对 ≥ 95%（若基线未知先达 95%） | 待补充：评测包条数 |
| 依据检索违规率 | 刹车异响题出现案例没有的「刹车油」或任意金额，记一次违规 | ≤ 基线 | 待补充 |
| 车主问诊结构 | 刹车题必须同时有【症状】【建议项目】【是否预约】，且建议预约到店 | ≥ 基线 | 可用 test_phase1 文案单测作回归，但仍需样本集 |

| 延迟 | P95 首 token 与整答 | 门店可接受（待补充 SLA） | 待补充 |

### 切换 API Base 的集成步骤

1. 起本地 Chat：vLLM 在 8001；curl `/v1/chat/completions` 用现网某条 guided 系统提示冒烟。
2. 改环境变量：`DEEPSEEK_BASE_URL=http://127.0.0.1:8001/v1`；`DEEPSEEK_API_KEY=dummy`；`DEEPSEEK_MODEL=car-repair-7b`。无需改 ChatOpenAI 调用点。
3. 保持检索不动：8010 仍为 bge-m3 +（可选新）reranker；`MILVUS_VECTOR_SIZE=1024` 不变。
4. 回归：pytest backend/tests；手动跑智能问答 SSE、guided_repair_chat、知识抽取、MCP search_knowledge/draft_quote。
5. 灰度：按门店或按用户开关切 BASE_URL；出问题秒切回云端 DeepSeek。
6. 若曾换 embedding：新集合灌数 → `python scripts/calibrate_thresholds.py` → 回填 `.env` 阈值 → 再切流量。

## 风险与回滚

| 风险 | 表现 | 缓解 | 回滚 |
| --- | --- | --- | --- |
| 幻觉零件/价格 | 刹车异响案例没有刹车油，模型仍建议换刹车油或报出合计 | SFT 用上面的问诊正例和报价 rejected；温度≤0.5（与现网一致） | 切回 DeepSeek；报价仍以规则引擎为准 |
| JSON 损坏 | 引导 options 解析失败 | 提高 JSON 样本占比；解码用 constrained / 重试 | 该路由临时回云 |
| 跨店隐私泄漏 | 模型吐出他店案例细节 | 按 store 分片训练或加店前缀控制；脱敏 | 下线该 adapter |
| 误换 embedding | 召回分数整体漂移 | 流程门禁禁止无标定发布 | 集合别名切回 knowledge 旧版 |
| CPT 指令退化 | 不会按系统提示拒答 | CPT 后必须 SFT；保留通用指令混合 | 弃用 CPT ckpt，从基座重做 SFT |
