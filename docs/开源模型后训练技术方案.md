# 汽修项目开源模型后训练技术方案

> 本文按仓库代码落仓，不把 Canvas 源文件放进仓库。配置名和路径以 `backend/app/core/config.py` 为准：召回是 `BAAI/bge-m3`，`MILVUS_VECTOR_SIZE=1024`，精排是 `Qwen/Qwen3-Reranker-0.6B`，Chat 仍走 `DEEPSEEK_BASE_URL` / `DEEPSEEK_MODEL`（代码默认 `deepseek-chat`，`.env.example` 示例 `deepseek-v4-flash`）。
>
> 相关文档：[代码完善清单](./代码完善清单.md)、[汽修 Agent 平台改造方案](./汽修-Agent-平台改造方案.md)、[docs 目录说明](./README.md)。
>
> 阈值脚本已支持 `--profile industrial|auto|all`。仓库仍没有 LLM 自动打分 harness；鉴权回归在 `backend/tests/test_auth_scope.py`。

> 优先后训练 Chat LLM（问诊/引导/JSON 输出），可选微调 Reranker；默认不换 bge-m3；训完用 OpenAI 兼容本地服务替换 `DEEPSEEK_BASE_URL` 灰度回现网。
>
> 依据仓 https://github.com/SHUN-EI/Car-Repair-System 代码事实（不以过时 README 为准）：`backend/app/core/config.py`、`embedding_server.py`、`guided_repair_agent.py`、`answer_generator.py`、`scripts/calibrate_thresholds.py`。

## 一句话决策

Chat LLM 是后训练主战场；Reranker 可做领域偏好微调；Embedding（bge-m3 / 1024 维）默认冻结，换模型必须重建 Milvus 集合并重跑 `calibrate_thresholds.py`，禁止未重建索引就改维度。

**「冻结 bge-m3」= 继续用现网 `bge-m3` 做向量化，不做后训练、也不换模型。** 不是「不用 bge-m3」。

## 目标与边界

目标：用开源模型把「门店汽修 Agent」从依赖云端 DeepSeek，推进到可离线/半离线的同协议本地 Chat 服务，同时保持现有 LangGraph/检索工具协议、门店隔离与报价规则引擎不变。

边界：本方案不改业务状态机，不重写 Vue 前端；报价草案 `create_draft` 仍走规则域（`domain/quote_service.py`），后训练不替代定价规则。不做全国多租户训练平台。训练样本必须按 `store_id` 隔离并脱敏。

| 项 | 说明 |
| --- | --- |
| 主训对象 | Chat LLM（问诊 SSE / 引导 JSON / 知识抽取 JSON） |
| 次训对象 | Qwen3-Reranker-0.6B（可选，成对相关性） |
| 默认冻结 | BAAI/bge-m3 + Milvus IVF_FLAT 1024 维 |
| 接回方式 | 改 `DEEPSEEK_BASE_URL` / `DEEPSEEK_MODEL`，保持 ChatOpenAI |
| 验收基线 | 现网 DeepSeek + bge-m3 + 现阈值 |

## 训什么、不训什么

```
Chat LLM（主训：SFT→偏好对齐）──主路径──► vLLM OpenAI API（替换 DEEPSEEK_*）
Reranker（可选：成对偏好/对比）──虚线──► 独立服务或同机
bge-m3（默认冻结）──仅当全量重索引──► 同上
报价/fitment/库存规则（不训，继续代码域）──协议保持──► 同上
```

| 对象 | 建议 | 理由 | 接回成本 |
| --- | --- | --- | --- |
| Chat LLM | 必须训 | 现网所有生成/问诊/JSON 引导都走 DeepSeek 兼容口；本地替换收益最大 | 低：改 BASE_URL/MODEL |
| Reranker | 优先可选 | 汽修术语/车型件号排序敏感；维度不变，不必重建向量库 | 中：替换 8010 内 rerank 权重或独立 `/v1/rerank` |
| Embedding | 慎训 / 慎换 | 集合 `knowledge`/`log_code` 绑死 1024 维与分数分布；换模型=全量 `sync_vectors` + 阈值重标定 | 高 |
| 报价引擎 | 不训 | `create_draft`/`rank_offers` 是确定性规则；可用 SFT 学如何组织 consult_text/建议项，不学造价格 | — |

硬约束：不要「先换个更好的 embedding 试试」而未重建索引。若必须做领域 embedding，单独开里程碑：新集合名（如 `knowledge_v2`）→ 双写对比 → 重跑 `calibrate_thresholds.py` → 再切 `MILVUS_COLLECTION`。

## 基座选型与方法对比

| 基座 | 许可注意 | 显存档（QLoRA 约） | 适配本项目理由 | 不选它的情况 |

| Qwen2.5-Instruct 7B | Apache-2.0（权重按卡确认） | 单卡 24GB 可训可推 | 中文指令强、工具/JSON 稳；门店单卡最小可行 | 长上下文多手册拼接不够时升级 14B |

| DeepSeek-R1-Distill-Qwen-7B/14B | 按卡确认 | 同档 | 与现网 DeepSeek 风格接近，迁移话术成本低 | 需要更强「拒答/只依据检索」约束时优先原版 Instruct + 强 SFT |
| 继续用云 DeepSeek | 商业 API | 0 本地显存 | 作对照基线与教师模型合成数据 | 整机离线门店 |

| 方法 | 对本项目用途 | 数据形态 | 阶段 | 注意 |
| --- | --- | --- | --- | --- |

## 数据工程

监督信号优先来自已发生的业务闭环，而不是凭空合成万能答案。

| 数据源 | 表/路径 | 可当什么监督 | 脱敏要点 |
| --- | --- | --- | --- |
| 结案工单 | `work_orders`：fault_description / fault_phenomenon / root_cause / solution_steps / used_parts / log_text / status=CLOSED\|COMPLETED / store_id | 诊断 SFT；知识抽取输入；CPT 语料 | 去车牌/VIN/手机/客户名；store_id 写入样本 meta，训练按店分片 |
| 知识条目 | `knowledge_items`（PUBLISHED）+ Milvus `knowledge` | RAG 回答 SFT 的检索案例侧；抽取目标 JSON | 审核通过稿优先；草稿不进训练 |
| 手册/故障码 | `manual_code_entries`、fault_code 映射；集合 `log_code` | CPT；引导步骤正例；rerank 正样本 | OEM 版权语料只做内部训练，不外发 |
| 问诊/引导会话 | Redis `guided_repair_session:*`（TTL 24h）+ 追踪后端（TRACING_BACKEND：ragflow/langfuse/local） | 多轮 SFT；JSON options 格式；车主三段结构 | 待补充：需落库导出流水，勿只依赖 TTL 会话 |
| 报价采纳 | `quotes`/`quote_lines`：草案→确认/改行；工单 used_parts | DPO：系统建议行 vs 技师最终行；不把单价当可生成标签乱训 | 金额可保留相对结构，客户标识剥离 |
| 负例 | 错件号、错车型 fitment、故意不相关手册段、闲聊触发 REPAIR_IRRELEVANT_REPLY | 拒答 SFT；rerank 负样本；意图阀门回归 | 合成时标注 synthetic=true |

### 采集办法（缺指标时先做这个）

1. **落库会话与采纳事件**：在 guided_repair/search SSE 结束时写 PG 表（建议新建 `training_events`：store_id、role、prompt、completion、retrieval_ids、user_action）。现网 Redis TTL 不够当训练集。待补充：表结构 PR。
2. **从结案工单批量导出**：SQL 过滤 store_id + 状态 CLOSED/COMPLETED；跑现有 knowledge_extractor 得 JSON 目标，人工抽检后进 SFT。
3. **教师模型蒸馏**：用现网 DeepSeek 对同一批检索上下文生成答案，技师只标「采纳/改写」→ 自然得到 DPO 对。
4. **负例工厂**：从 fitment 不匹配的备件、跨设备手册、`repair_intent_fast_check` 应拦截的闲聊模板生成 rejected。

### JSONL Schema（可直接喂 LLaMA-Factory）

Chat SFT 用 OpenAI messages 风格一行一条。必填顶层字段：`id`、`meta.store_id`、`meta.task`、`messages[]`；assistant 对引导任务必须是可解析 JSON（message / options / status）。

| 字段 | 示例值 | 说明 |
| --- | --- | --- |
| id | sft-wo-1203 | 样本主键 |
| meta.store_id | 1 或 null | 门店隔离；公开手册可 null |
| meta.task | guided_json / consult_chat / extract_kb / refuse | 任务桶，便于配比抽样 |
| messages[0].role | system | 贴现网 SYSTEM_PROMPT / CONSULT / 抽取提示 |
| messages[1].role | user | 故障描述 + 参考案例截断文本 |
| messages[2].role | assistant | 引导 JSON 或三段问诊正文 |

DPO 一行一条：id、meta.store_id、meta.task（quote_lines_pref 或 answer_pref）、prompt（含检索与草案上下文）、chosen（技师确认后叙述）、rejected（被删改的错误件/错项叙述）。不要把单价当作可自由生成的标签。

Reranker 成对：query（如「帕萨特 1.8T 怠速抖动」）、positive（正确手册/案例）、negative（错误车型或无关件号说明）。

Domain CPT：一行一篇纯文本字段 text（故障现象/处理方法结构），meta.store_id 对公开手册置空、门店私有案例必填。

### 脱敏与门店隔离规则

- store_id 写入每条样本 meta；训练 DataLoader 禁止无过滤的全库 shuffle；对外输出模型时按合同决定是否只含本连锁数据
- 正则/词典剥离：车牌、VIN、手机、身份证、详细地址、客户姓名；保留车型品牌/年款/故障码
- log_text 只抽错误码与信号词进训练（与 knowledge_extractor 规则一致），禁止整段十六进制日志进 CPT
- 导出物放门店内网对象存储；训练机出网关闭或仅镜像源

## 三阶段训练路线

继续预训练与 SFT/偏好对齐必须分开跑、分开存 checkpoint，禁止 CPT+SFT 一把梭导致指令跟随塌陷。

### 阶段 A — Domain CPT（可选）

1. 语料打包：PUBLISHED 知识 + 手册结构化正文 + 脱敏结案方案；目标 5 万~50 万 tokens 起（待补充：库真实 token 量，用脚本 wc/tokenizer 统计）。
2. 训练：LLaMA-Factory template: qwen，stage: pt，lr≈1e-5，epoch 1~2，seq 2048/4096，保存 `cpt-qwen25-7b`。
3. 门禁：通用指令集抽测不崩；困惑度相对基座下降；禁止背出训练集里的真实车牌（用探针集）。

### 阶段 B — SFT（主路径）

任务配比建议（可按样本数再调；无数据的桶先空着并采集）：引导 JSON 30%；检索问答（严格依据案例）25%；车主问诊三段 15%；知识抽取 JSON 15%；拒答/闲聊 10%；工具叙述（如何调用检索/draft_quote 的自然语言说明）5%。

LoRA 超参起点（7B QLoRA，单卡 24GB）：

| 项 | 值 |
| --- | --- |
| quantization | bnb qlora 4bit |
| lora_rank | 16（JSON 不稳再试 32） |
| lora_alpha | 32 |
| lora_dropout | 0.05 |
| target_modules | q_proj,k_proj,v_proj,o_proj,gate_proj,up_proj,down_proj |
| lr | 2e-4 |
| batch | 微批 2 × grad_accum 8 |
| epochs | 2~3，早停看 valid JSON 解析率 |
| max_len | 4096（含检索案例截断，对齐现网 content 截断习惯） |

命令骨架：

```bash
CUDA_VISIBLE_DEVICES=0 llamafactory-cli train examples/train_qlora/qwen25_7b_sft_car.yaml
```

YAML 关键字段：`model_name_or_path` 指向 Qwen2.5-7B-Instruct（或阶段 A 的 CPT 合并权重）；`adapter_name_or_path` 为空；`stage=sft`；`do_train=true`；`finetuning_type=lora`；`dataset=car_repair_sft`；`template=qwen`；`output_dir=saves/car-sft-7b`；`quantization_bit=4`。

Unsloth 等价路径（更快原型）：`FastLanguageModel.from_pretrained(..., load_in_4bit=True)` → `get_peft_model` → `SFTTrainer`；导出仍用 HF / merged 16bit 供 vLLM。

### 阶段 C — DPO/ORPO（采纳偏好）

1. 构造偏好对：chosen=技师最终采纳话术/改后报价叙述；rejected=模型原稿或被驳回知识。样本不足 500 对时用 ORPO 或仅做小学习率 DPO 1 epoch。
2. 训练：`stage=dpo`，从 SFT adapter 继续；lr≈5e-6~1e-5；beta≈0.1。
3. 门禁：同题对比 SFT：JSON 合法率不下降；「只依据检索」违规率不升；门店私有实体探针不泄漏。

### Reranker 并行（可选）

冻结 embedding；用 FlagEmbedding / transformers 对 Qwen3-Reranker-0.6B 做成对 CE 或 Listwise。导出后替换 embedding_server 内权重路径（`_RERANKER_LOCAL_CANDIDATES`），接口 `/v1/rerank` 不变。验收：固定 query 集上 nDCG@10 / MRR 相对原版提升（待补充：标注集规模）。

## 评测与上线

基线固定为：现网 `DEEPSEEK_*` + bge-m3 + 当前阈值。本地模型必须在同一批「冻结评测包」上对比；数值列待补充（先建包再填）。

| 门禁项 | 定义方式 | 通过线（相对基线） | 现状 |
| --- | --- | --- | --- |
| 引导 JSON 合法率 | 解析 options/status 字段成功占比 | ≥ 基线 - 1pp，且绝对 ≥ 95%（若基线未知先达 95%） | 待补充：评测包条数 |
| 依据检索违规率 | 人工/规则：出现案例未出现的部件名/数值 | ≤ 基线 | 待补充 |
| 车主问诊结构 | 是否含症状理解/建议项目/是否预约三段 | ≥ 基线 | 可用 test_phase1 文案单测作回归，但仍需样本集 |
| 闲聊拦截 | 与 repair_intent_* 一致应拒则拒 | 不低于现网阀门+模型组合 | 有单元测试可复用 |
| 端到端有用率 | 技师盲评 A/B（DeepSeek vs 本地） | 本地胜出或打平 ≥ 50% | 待补充：组织盲评 |
| 检索侧（若动 rerank） | nDCG@10 / 人工 top3 相关 | ≥ 基线 | 待补充标注 |
| 延迟 | P95 首 token 与整答 | 门店可接受（待补充 SLA） | 待补充 |

### 切换 API Base 的集成步骤

1. 起本地 Chat：vLLM 在 8001；curl `/v1/chat/completions` 用现网某条 guided 系统提示冒烟。
2. 改环境变量：`DEEPSEEK_BASE_URL=http://127.0.0.1:8001/v1`；`DEEPSEEK_API_KEY=dummy`；`DEEPSEEK_MODEL=car-repair-7b`。无需改 ChatOpenAI 调用点。
3. 保持检索不动：8010 仍为 bge-m3 +（可选新）reranker；`MILVUS_VECTOR_SIZE=1024` 不变。
4. 回归：pytest backend/tests；手动跑智能问答 SSE、guided_repair_chat、知识抽取、MCP search_knowledge/draft_quote。
5. 灰度：按门店或按用户开关切 BASE_URL；出问题秒切回云端 DeepSeek。
6. 若曾换 embedding：新集合灌数 → `python scripts/calibrate_thresholds.py` → 回填 `.env` 阈值 → 再切流量。

| 风险 | 表现 | 缓解 | 回滚 |

| 幻觉零件/价格 | 问诊编造案例没有的项目 | SFT 强化「只依据检索」；负例；温度≤0.5（与现网一致） | 切回 DeepSeek；报价仍以规则引擎为准 |
| JSON 损坏 | 引导 options 解析失败 | 提高 JSON 样本占比；解码用 constrained / 重试 | 该路由临时回云 |
| 跨店隐私泄漏 | 模型吐出他店案例细节 | 按 store 分片训练或加店前缀控制；脱敏 | 下线该 adapter |
| 误换 embedding | 召回分数整体漂移 | 流程门禁禁止无标定发布 | 集合别名切回 knowledge 旧版 |
| CPT 指令退化 | 不会按系统提示拒答 | CPT 后必须 SFT；保留通用指令混合 | 弃用 CPT ckpt，从基座重做 SFT |
