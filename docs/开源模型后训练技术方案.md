# 汽修项目开源模型后训练技术方案

> 本文日期：2026-11-25。在 2026-11-20 版现网接线的基础上重写为完整、可独立阅读的技术方案，方法顺序对齐附件教程 *tiny-agentic-lab：三阶段训练系统*（SFT → GRPO → 有条件的 OPD），数据和模型全部换成本仓库现网，而不是再写一份并列的数学训练方案，也不把 Canvas 源文件放进仓库。
>
> 配置名和路径以 `backend/app/core/config.py` 与 `backend/.env.example` 为准：召回是 `BAAI/bge-m3`，`VECTOR_DIM=1024`，精排是 `BAAI/bge-reranker-v2-m3`，Chat 现网走 `CHAT_LLM_MODE`（默认 `cloud`：阿里云百炼兼容接口上的 `qwen-plus`；`local`：本机 vLLM `Qwen/Qwen2.5-7B-Instruct`）。旧的 `DEEPSEEK_*` 仅在 `CHAT_LLM_MODE=deepseek` 时生效。调用点统一走 `make_chat_llm()`。和 README 冲突时以代码为准。
>
> 相关文档：[开源模型后训练执行手册](./开源模型后训练执行手册.md)（数据导出、JSONL、训练命令与接回步骤）、[代码完善清单](./代码完善清单.md)、[汽修 Agent 平台改造方案](./汽修-Agent-平台改造方案.md)、[docs 目录说明](./README.md)。
>
> 阈值脚本已支持 `--profile industrial|auto|all`。仓库里没有 LLM 自动打分 harness，也还没有冻结好的汽修黄金评测集或 `training_events` 表。鉴权回归在 `backend/tests/test_auth_scope.py`，对话切换回归在 `backend/tests/test_chat_llm_mode.py`，引用与多源融合回归在 `backend/tests/test_rag_source_cite.py`、`backend/tests/test_rag_multisource_rrf.py`。
>
> 优先后训练 Chat LLM（问诊 / 引导 / JSON 输出 / 检索助手决策）；可选在现网 `bge-reranker-v2-m3` 上做领域微调；默认不换、不训 bge-m3。训完把 `CHAT_LLM_MODE=local` 并指向本机 vLLM 灰度回现网。下文中的方案对照都是基于现网接线的技术对照，不是已经跑完并落档的 POC 结果。附件教程里的正确率数字只属于该教程实验，不是本项目已经取得或承诺达到的指标。

## 一句话决策

主训对象是现网本地 Chat 学生模型 `Qwen2.5-7B-Instruct`（与 `CHAT_LOCAL_MODEL` 一致）。训练顺序是：先用本机 7B 做一次推理冒烟，再做带参考轨迹的 SFT，再在有组内差异的 Agent 任务上做 GRPO；只有当教师云端 `qwen-plus` 相对学生仍有可测的分布差距时，才考虑 OPD。Reranker 可在现网 `bge-reranker-v2-m3` 上做领域偏好微调；Embedding（bge-m3 / 1024 维）默认冻结。换 embedding 必须重建 PostgreSQL 中的 embedding 并重跑 `calibrate_thresholds.py`，禁止未重建索引就改维度。训完的服务名建议为 `car-repair-7b`，必须与 vLLM `--served-model-name` 及 `CHAT_LOCAL_MODEL` 一致。

**「冻结 bge-m3」= 继续用现网** `bge-m3` **做向量化，不做后训练、也不换模型。** 不是「不用 bge-m3」。报价草案仍走规则引擎，不训报价引擎。

## 与附件教程的差异

附件是 tiny-agentic-lab 的数学 + 合成 Agent 教程，基座是 Qwen3.5-2B。本方案只吸收它的方法顺序和工程教训，不搬它的数据、奖励、评测集和超参数字。

| 项 | 附件教程 | 本项目采用或废弃 |
| --- | --- | --- |
| 训练顺序 | 环境验证 → SFT → 题目筛选 → 数学 GRPO / Agent GRPO → 有条件 OPD → 程序化评测（含 pass³） | **采用**同一顺序；强化学习默认走 Agent 线 GRPO，数学 GRPO 不作主路径 |
| 学生模型 | Qwen3.5-2B；教程要求 `transformers>=5.20` 才能加载该架构 | **改为**现网 `Qwen/Qwen2.5-7B-Instruct`。是否需要 `transformers>=5.20` 以实际加载的架构为准，不把该版本写成硬性前提 |
| 教师 / 基线 | 教程用自己的 GRPO 检查点当教师；实验 A 把标准答案塞进教师提示的自蒸馏，MATH-500 从 47.5% 降到 2.5%（**仅属教程实验**） | **教师、验收基线和对照参考都是现网云端** `qwen-plus`（`CHAT_LLM_MODE=cloud`，DashScope 兼容接口）。不是 DeepSeek。禁止把最终答案塞进教师提示做自蒸馏 |
| 主数据 | DeepScaleR / MATH-500，思考模式 `<think>` + 「答案是 X」 | **废弃**数学题和思考模式主格式。教材是已完成或已归档工单、已发布知识、原厂手册与 OBD、已发布 FAQ，以及教师 `qwen-plus` 在现网提示词下写出的合格轨迹。聊天模板用 Qwen2.5-Instruct |
| SFT 教材策略 | 拒绝采样只会留下模型已经会的题，改用参考解题过程 | **采用**这一教训：不以拒绝采样作为主教材来源 |
| SFT 训练技巧 | 只对助手回复算损失、LoRA、显存紧时分块损失 + 梯度检查点 | **采用**这些技巧。7B 比教程 2B 更吃显存，**不要**把教程的 `r=16` / `batch=4` / 约 16GB 峰值当成本项目默认值；16GB 卡上往往要走 QLoRA，具体峰值以实测为准，本文不编造测得数字 |
| GRPO | 数学线用 SymPy 判分；Agent 线（多步工具、干扰工具、工具失败恢复）相对提升最大（教程记录新任务 46.7%→86.7%，**仅属教程实验**） | **采用** Agent 线作为本项目默认 RL 阶段，用来替换旧方案里默认的可选 DPO/ORPO。**废弃**数学 GRPO 和 SymPy 作为主奖励。奖励必须程序化，仓库里没有 LLM-as-judge |
| 筛题 | 必须按训练时的采样条件多次生成，只保留有对有错的题；全对或全错组跳过 | **采用** |
| 轨迹损失 | 只对模型自己生成的 token 算损失，工具返回不当预测目标；不要在同一批里对长短不一的轨迹左填充 | **采用** |
| OPD | 师生分布过近则几乎无信号；改散度也救不了 | **有条件采用**：先确认 `qwen-plus` 相对本地 7B 仍有差距，再做；差距不明显就停在 SFT + GRPO |
| 评测 | MATH-500、程序化等价判断、pass³（同一题独立跑 3 次全对才算过） | **采用**冻结的汽修 held-out 集、程序化打分、可选的 pass³ 稳定性。**MATH-500 不是本产品的验收指标**。评测集目前尚未建成，下文指标一律写待补充，不把教程数字当作本项目目标 |
| 默认 RL 备选 | 教程未把 DPO/ORPO 当作主路径 | 若程序化奖励或 Agent 环境尚未就绪，DPO/ORPO 可以仍作备选，不再作为默认第三阶段 |

教程第 10 章的五条结论，映射到本项目后仍然成立，但必须用汽修任务和现网模型重新验证，不能直接引用其百分比：SFT 改善输出格式与组织；GRPO 的关键是组内奖励差异；OPD 取决于教师信号；不要把最终答案塞进教师提示；训练中要按独立评测决定是否扩池或改策略。

## 目标与边界

目标：用开源模型把「门店汽修 Agent」从依赖云端对话 API（现网默认是阿里云百炼 `qwen-plus`），推进到可离线或半离线的同协议本地 Chat 服务，同时保持现有 LangGraph / 检索工具协议、门店隔离与报价规则引擎不变。

边界：本方案不改业务状态机，不重写 Vue 前端；报价草案 `create_draft` 仍走规则域（`domain/quote_service.py`），后训练不替代定价规则。不做全国多租户训练平台。训练样本必须按 `store_id` 隔离并脱敏。不把 Redis 24 小时会话或尚未自动落库的咨询聊天直接当训练集。

| 项 | 说明 |
| --- | --- |
| 主训对象 | Chat LLM（问诊 SSE / 引导 JSON / 知识抽取 JSON / 检索助手工具选择） |
| 次训对象 | 现网 `BAAI/bge-reranker-v2-m3`（可选，成对相关性） |
| 默认冻结 | BAAI/bge-m3 + PostgreSQL pgvector HNSW 1024 维 |
| 接回方式 | 设 `CHAT_LLM_MODE=local` 并指向本机 vLLM，保持 `make_chat_llm()` / ChatOpenAI |
| 验收基线 | 现网 `CHAT_LLM_MODE=cloud`（`qwen-plus`）+ bge-m3 + 现阈值 |
| 产品层第一类 Agent | 只有两个：`ConsultGuideAgent`、`WorkOrderAgent`。`RetrievalAssistantAgent` 是咨询门面内部的自定义 ReAct 循环（`MAX_ITERATIONS=5`），适合作为 Agent-GRPO 环境，不是第三个第一类 Agent |

## 训什么、不训什么

```
Chat LLM（主训：SFT → Agent GRPO → 有条件 OPD）──主路径──► vLLM OpenAI API（`CHAT_LLM_MODE=local` + `CHAT_LOCAL_*`）
Reranker（可选：在 bge-reranker-v2-m3 上做成对偏好/对比）──虚线──► 8010 `/v1/rerank`
bge-m3（默认冻结）──仅当全量重索引──► PostgreSQL embedding 列
报价/fitment/库存规则（不训，继续代码域）──协议保持──► 同上
```

| 对象 | 建议 | 理由 | 接回成本 |
| --- | --- | --- | --- |
| Chat LLM | 必须训 | 现网所有生成 / 问诊 / JSON 引导 / 检索决策都走 `make_chat_llm()`；本地替换收益最大 | 低：改 `CHAT_LLM_MODE=local` 与 `CHAT_LOCAL_*` |
| Reranker | 优先可选 | 汽修术语 / 车型件号排序敏感；维度不变，不必重建向量列。除「与现网精排同架构、接回成本低于换 embedding」外，代码/文档未另写必须微调的选型理由 | 中：在现网 `bge-reranker-v2-m3` 上微调后替换 8010 内权重，或把导出目录放到 `_RERANKER_LOCAL_CANDIDATES` 最前。不要把 Qwen3-Reranker 权重直接塞进该列表（加载器已改为 FlagReranker） |
| Embedding | 慎训 / 慎换 | `knowledge_items` / 手册块 / OBD 等表的 embedding 列绑死 1024 维与分数分布；换模型=全量重写 embedding + 阈值重标定 | 高 |
| 报价引擎 | 不训 | `create_draft` / `rank_offers` 是确定性规则；可用 SFT 学如何组织 consult_text / 建议项，不学造价格 | — |

硬约束：不要「先换个更好的 embedding 试试」而未重建索引。若必须做领域 embedding，单独开里程碑：先双写或另列新 embedding 列 → 对比评估 → 重跑 `backend/scripts/calibrate_thresholds.py` → 再切换查询列。不要未重建向量就改维度。没有集合别名可回切，回滚只能切回旧的 embedding 列或备份。

学生模型取现网已接线的 `CHAT_LOCAL_MODEL=Qwen/Qwen2.5-7B-Instruct`，以便训完按同协议接回。除「与现网本地接线一致」外，代码/文档未另写必须选 7B 而不是 14B 或其他指令模型的选型理由。若后续确认 7B 在多手册拼接上不够用，再单独评估升级，不在本方案里提前换基座。

教师、合成示范和验收对照一律用现网默认云端 `qwen-plus`，不要改用 DeepSeek，也不要把教程里的 GRPO 检查点当成教师。`DEEPSEEK_*` 只是兼容模式。

## 方法总览

实施顺序如下，阶段之间分开存 checkpoint，禁止把 CPT、SFT、GRPO 混在一次训练里一把梭。

1. **环境验证**：先用未微调的本地 `Qwen2.5-7B-Instruct` 完成一次推理，确认 GPU、加载和生成都正常，再改训练代码。
2. **SFT（必做）**：用参考轨迹而不是拒绝采样当主教材，让模型学会现网系统提示下的格式、引用、拒答和 JSON。
3. **GRPO（SFT 之后的默认强化学习）**：在有组内差异的检索 / 问诊 Agent 任务上，用程序化奖励做组内相对优势更新。
4. **OPD（有条件）**：仅当教师 `qwen-plus` 相对学生仍有可测差距时再做；否则停在 SFT + GRPO。
5. **评测与接回**：冻结 held-out 汽修集，对比未微调 7B、SFT、GRPO 以及云端 `qwen-plus`；通过后再按 `CHAT_LLM_MODE=local` 灰度上线。

旧方案中的 Domain CPT 和 DPO/ORPO 降为可选支线，见后文「可选支线」。

## 第 0 步：环境准备与本地推理验证

在修改训练代码或导出大量数据之前，先确认训练机会加载并跑通现网本地学生模型。

1. 安装支持 CUDA 的 PyTorch，而不是 CPU 版。版本与当前 Python、CUDA、官方安装索引对齐后，再执行 `python -c "import torch; print(torch.__version__, torch.cuda.is_available())"`，期望第二项为 `True`。
2. 安装训练依赖（transformers、accelerate、PEFT / LLaMA-Factory 或等价栈）。不要把教程针对 Qwen3.5 的 `transformers>=5.20` 写成硬性要求；以 `Qwen2.5-7B-Instruct` 能正确加载为准。
3. 准备权重 `Qwen/Qwen2.5-7B-Instruct`（与 `CHAT_LOCAL_MODEL` 一致）。
4. 先不加载 LoRA，做一次生成冒烟：系统提示用现网某条 `CONSULT_CHAT_SYSTEM_PROMPT` 或引导 `SYSTEM_PROMPT` 的原文，确认输出是可读中文，而不是加载失败或乱码。
5. 若这一步失败，先排查环境或模型加载，不要进入 SFT。

推理接回用的 vLLM 可以稍后在 SFT 完成后再拉起，但训练机和推理机都应避免占用 embedding 服务的 8010 端口。`.env.example` 中的示例命令是：

```bash
vllm serve Qwen/Qwen2.5-7B-Instruct --host 0.0.0.0 --port 8001 --served-model-name Qwen/Qwen2.5-7B-Instruct
```

训完接回时，把 `--served-model-name` 和 `CHAT_LOCAL_MODEL` 一起改成如 `car-repair-7b`。

## 数据工程

监督信号优先来自已发生的业务闭环，以及教师 `qwen-plus` 在**同一套现网提示词**下写出的合格参考轨迹。不要让未微调的学生模型自己生成后再做拒绝采样，当作 SFT 的主教材——附件教程已经说明，这样只会留下模型已经会的题。

### 允许导出的来源

| 来源 | 导出条件 | 用途 |
| --- | --- | --- |
| 工单 | 状态为 `COMPLETED` 或 `ARCHIVED` 的工单，或 PDF 导入并已确认入库的工单 | `extract_kb`、引导 / 问诊的参考情形、可选 CPT 纯文本 |
| 工单知识 | `knowledge_items` 中 `source_type=WORK_ORDER` 且已 `PUBLISHED` | 同上，字段更干净时可优先用 |
| 原厂手册 / 技术手册 / 设备手册错误码 / OBD | 已入库并参与现网检索的公开或门店授权文本 | `retrieve_qa` 的权威来源、冲突题的高优先级侧 |
| 已审 FAQ | `consult_faqs` 中 `status=PUBLISHED`（模型注释为审核通过后的可检索客服知识） | 低优先级引用、常见问诊说法 |
| 教师轨迹 | 在现网系统提示、同等检索截断和温度设置下，用 `CHAT_LLM_MODE=cloud` 的 `qwen-plus` 生成，再经质检 | 覆盖学生当前不会的题，作为 SFT 参考过程 |

现网 `_auto_publish_knowledge` 在工单进入 `COMPLETED`、`ARCHIVED`，或 PDF 导入确认时触发；钉钉移动端在 `ARCHIVING` 时也会调用。`CLOSED` 是汽修车道结案状态，转入时会排期回访，**不会**调用 `_auto_publish_knowledge`。因此导出工单时不要默认按 `CLOSED` 过滤，否则会漏掉自动落库的知识，也会把尚未抽取知识的结案工单误当成已发布教材。

### 不能直接当训练集的数据

- `consult_conversations` / `consult_messages` 表已经存在，但现网咨询聊天不会自动写入这两张表（脚本 `backend/scripts/seed_rag_multisource.py` 只会预置已发布 FAQ）。在打通落库、脱敏和人工审核之前，不要从这两张表导出。
- 引导 / 专家 / MCP 员工会话存在 Redis 里，TTL 为 24 小时（`memory_service.py` 中 `GUIDED_REPAIR_SESSION_TTL = 24 * 3600` 等），过期即消失，不能当训练集。
- `training_events` 表目前不存在，可以作为后续采集方案提出，但不要写成已经落地。
- `log_text` 只抽错误码与信号词（与 `knowledge_extractor` 规则一致），禁止整段十六进制日志进训练。
- 未发布（`DRAFT` / `DEPRECATED`）的知识或 FAQ、未完成的工单、跨店未授权数据，一律不进训练。

### 一条到店闭环（六类 SFT 样本）

下面用门店里真实会走到的一条闭环说明每类样本长什么样。知识正文取自 `backend/app/domain/auto_repair_seed.py` 已发布样例，报价价格仍由目录 / `create_draft` 取值。这是为了说明样本形态，不是一份已经导出的训练集。

门店 `store_id=1`。车辆是 2018 款大众速腾 1.4T，里程约 6 万公里。样本里保留品牌、车系、年款、排量、故障码；车牌、VIN、手机、客户姓名在导出时替换掉。

车主在问诊里说：「踩刹车有金属摩擦声，低速点刹更尖。」检索命中已发布知识「【汽修样例】刹车异响与刹车盘片检查」。接车后技师又读到 P0300，热车怠速抖动。结案工单把这次处理写成知识；报价草案里的项目名称来自问诊「建议项目」，单价来自配件目录，技师确认时删掉了模型多写的施工项。

| 环节 | 业务里发生的事 | 变成哪条训练样本 |
| --- | --- | --- |
| 车主问诊 | `scene=consult`，系统提示 `CONSULT_CHAT_SYSTEM_PROMPT`，回复固定【症状】【建议项目】【是否预约】 | SFT `consult_chat` |
| 技师排查 P0300 | `GuidedRepairAgent.SYSTEM_PROMPT`，每步 2～3 个选项，只引用手册情形 | SFT `guided_json` |
| 智能问答引用 | `AnswerGenerator.SYSTEM_PROMPT` / `CONSULT_SYSTEM_PROMPT`：结论后注明来源；冲突时按 `SOURCE_PRIORITY` | SFT `retrieve_qa` |
| 结案沉淀 | `_auto_publish_knowledge` 在 `COMPLETED` / `ARCHIVED` / PDF 确认时触发，字段进 `KnowledgeExtractorAgent` | SFT `extract_kb` |
| 闲聊 | 「帮我查这个月工资」被 `repair_intent_fast_check` / `repair_intent_check` 判为无关 | SFT `refuse`，回复用当时代码里的 `REPAIR_IRRELEVANT_REPLY` 原文 |
| 工具叙述 | 说明建议项目会进报价草案，价格由目录计算；冲突时按原厂手册 / OBD 优先；检索助手选择 `vector_search` / `bm25_search` 等 | SFT `tool_narration` |

建议配比（可按实际样本数再调；无数据的桶先空着并采集）：`guided_json` 25%，`retrieve_qa` 25%，`consult_chat` 15%，`extract_kb` 15%，`refuse` 10%，`tool_narration` 10%。

脱敏前后各留一句，训练只吃右边：

```text
原文：车主张伟 13812348000 京A12345 打电话说 2018 大众速腾 1.4T 踩刹车有金属摩擦声
样本：车主[客户] [手机] [车牌] 打电话说 2018 大众速腾 1.4T 踩刹车有金属摩擦声
```

#### 车主问诊（consult_chat）

系统提示贴现网 `GuidedRepairAgent.CONSULT_CHAT_SYSTEM_PROMPT` 原文。检索案例按对应调用点截断（问诊 compact / brief 路径为 600 字）。assistant 只能复述案例里写明的检查项。案例写的是「盘面起槽或片磨到限位时更换」，不能写成「已经要换盘换片」，也不能报一个目录里才有的价格。温度与现网一致，为 0.5。

#### 技师引导（guided_json）

系统提示贴现网引导 `SYSTEM_PROMPT`。assistant 必须是可解析 JSON，含 `message` / `options` / `status`（如 `awaiting_action`）。选项只给到手册或案例写明的下一步，例如 P0300 只给到「读取失火计数」，不要一次跳到换件。

#### 检索问答与引用（retrieve_qa）

结论后必须注明出处：OBD、原厂手册、技术手册、设备手册错误码、工单案例或客服知识。不同来源冲突时，原厂手册与 OBD 优先于技术手册 / 设备手册错误码，再优先于工单案例，工单案例优先于已审客服知识。检索结果不足以判断时，直接写知识库未覆盖，不要用通用经验补全。引用的来源编号必须能在当条样本的检索片段里找到。

#### 结案抽取（extract_kb）

字段对齐 `KnowledgeExtractorAgent` 的现网 schema，只从工单已有字段抽取，不编造未出现的配件或步骤。

#### 拒答（refuse）

回复必须原样抄写现网 `REPAIR_IRRELEVANT_REPLY`（定义在 `backend/app/rag/retrieval_flow.py`）：

```text
这条消息和设备维修无关，我先不继续处理。
如果是设备故障，请描述具体的设备和故障现象，例如：
注塑机温度过高、空压机不启动、CNC 主轴 SV0436 报警。
```

注意：现网原文仍是工业设备口吻（注塑机 / 空压机 / CNC）。若要改成汽修举例，必须先改代码里的常量并回归意图阀门，再刷新拒答样本。不要只在训练集里擅自改写成「刹车异响」之类的汽修口吻，否则本地模型会上线后与现网拦截文案不一致。

#### 工具叙述（tool_narration）

覆盖两类信号：生成层说明「建议项目进入报价草案、价格由目录计算、冲突按优先级取舍」；检索助手在 `RetrievalAssistantAgent` 的动作空间里选择工具（`vector_search`、`bm25_search`、`conditional_query`、`graph_query`、`rewrite_query`、`finish`），并叙述为何选择，而不是直接把工具返回文本当成助手要预测的内容。

### 质量门禁（对应教程第 2 章，改成汽修规则）

参考轨迹也不能不经检查就进训练。建议依次执行：

1. **长度**：过短（缺少必要步骤、无法解析的空 JSON、拒答被截断）丢掉；过长按对应调用点的截断习惯和分词后的 `max_len` 丢掉。字符数不等于 token 数，超长以分词为准。
2. **一致性**：
   - `guided_json` / `extract_kb` 必须能按现网 schema 解析；
   - `retrieve_qa` / `consult_chat` 的结论和引用必须对得上当条样本给出的检索片段，不能引入片段外的配件、价格或步骤；
   - 冲突题必须遵守 `SOURCE_PRIORITY`，不得只采用低优先级结论；
   - `refuse` 必须与当时的 `REPAIR_IRRELEVANT_REPLY` 原文一致。
3. **训练 / 评测去重**：候选样本与冻结评测包做题面或业务主键去重，防止评测题泄漏进训练。划分训练、验证、测试后做交叉检查，三类集合不应有重复样本。
4. **教师轨迹复核**：教师输出也要过上述一致性检查。教师提示使用现网系统提示和检索片段，**不要**把最终标准答案提前塞进教师上下文。

### JSONL Schema

Chat SFT 用 OpenAI messages 风格一行一条，可喂 LLaMA-Factory 或等价训练器。必填顶层字段：`id`、`meta.store_id`、`meta.task`、`messages[]`。公开 OBD / 手册的 `meta.store_id` 可为空；门店工单必须带店号。

| 字段 | 示例值 | 说明 |
| --- | --- | --- |
| id | sft-guided-p0300-1 | 样本主键 |
| meta.store_id | 1 | 所属门店；公开手册可 null |
| meta.task | guided_json | 同一次到店的其他桶：consult_chat / retrieve_qa / extract_kb / refuse / tool_narration |
| meta.synthetic | false | 教师合成轨迹标 true，便于抽查 |
| messages[0].role | system | 贴现网对应 SYSTEM_PROMPT / CONSULT / 抽取提示原文 |
| messages[1].role | user | 用户问题 + 按调用点截断后的检索情形 |
| messages[2].role | assistant | 引导任务必须是可解析 JSON；问诊为三段结构；拒答为现网原文 |

多轮工具轨迹（给 SFT 的示范或给 GRPO 的回放）应保留完整 messages；训练时只对助手生成的 token 打标签，工具返回设为忽略。

### 脱敏与门店隔离

- `store_id` 写入每条样本 meta；训练 DataLoader 禁止无过滤的全库 shuffle；对外输出模型时按合同决定是否只含本连锁数据。
- 正则 / 词典剥离：车牌、VIN、手机、身份证、详细地址、客户姓名；保留车型品牌 / 年款 / 故障码。
- 导出物放门店内网对象存储；训练机出网关闭或仅镜像源。

### 采集办法（缺会话落库时先做这个）

1. 先从 `COMPLETED` / `ARCHIVED` 工单、已发布 `knowledge_items` 和已发布 FAQ、手册 / OBD 导出并脱敏。
2. 用同一套现网提示词，让教师 `qwen-plus` 在检索片段约束下补齐学生还不会的轨迹，再人工或规则质检。
3. 同步设计冻结评测包（与训练去重），不要等模型训完再临时选题。
4. 若要持续采集线上采纳 / 改写，可新建 `training_events`（建议字段：`store_id`、角色、prompt、completion、retrieval_ids、user_action），或先打通 `consult_conversations` / `consult_messages` 并做脱敏与审核后再导出。这两件事目前都还没有落地，需要单独排期。

## 阶段一：SFT（必做）

SFT 是 GRPO 之前必须完成的一步。附件教程的教训是：基座模型输出往往过长、格式不统一，不便于自动提取和程序化奖励；SFT 先把格式和任务组织稳住，后续强化学习才有可计算的奖励。

### 训练技巧

- 使用 Qwen2.5-Instruct 的 chat template 渲染完整对话，**只对助手回复计算损失**，系统提示、用户问题和工具返回的 label 设为忽略（如 `-100`）。不要把教程的 `<think>` + 「答案是 X」当作本项目主格式。
- 用 LoRA（或 QLoRA）只更新少量参数，导出时可合并为供 vLLM 加载的权重。
- 显存紧张时采用分块交叉熵和梯度检查点。Qwen2.5-7B 的词表和激活都大于教程中的 2B，16GB 卡上往往需要 QLoRA；24GB 单卡可作为较舒适的 SFT 起点。具体 batch、秩、学习率和峰值显存必须在本机重测后写入训练配置，本文不给出冒充实测的数字，也不把教程的 `r=16` / `batch=4` / 约 16GB 当默认值。
- 训练与现网截断习惯对齐：按任务选用 600 / 800 / 400 / 1500 的内容截断，再设置分词后的 `max_len`。
- 建议保留少量通用指令或安全拒答混合，降低只拟合门店话术导致的指令跟随退化。若先做了可选 CPT，必须再跑本阶段 SFT，分开存盘。

命令骨架（配置文件放私有训练仓，本仓库不必入库训练权重）：

```bash
CUDA_VISIBLE_DEVICES=0 llamafactory-cli train examples/train_qlora/qwen25_7b_sft_car.yaml
```

YAML 关键字段建议：`model_name_or_path` 指向 `Qwen/Qwen2.5-7B-Instruct`（或可选 CPT 合并权重）；`stage=sft`；`finetuning_type=lora`；`dataset` 指向本项目质检后的 JSONL；`template=qwen`；`quantization_bit` 按显存决定。Unsloth 只作为更快的原型路径，导出仍用 Hugging Face / merged 权重供 vLLM。

### SFT 门禁

在冻结评测包上对比未微调的本地 7B 与 SFT 检查点，并同时看云端 `qwen-plus` 对照。至少检查：引导 JSON 可解析率、问诊三段结构、引用来源是否匹配检索片段、冲突优先级、拒答是否与现网原文一致、「只依据检索」违规率。数值待评测包建成后填写，不在这里预设通过百分比。JSON 合法率明显变差或拒答走样时，停止进入 GRPO。

## 阶段二：GRPO（默认强化学习，以 Agent 线为主）

SFT 之后，用组相对策略优化继续提升「会做对、且多次采样更稳」的能力。对本项目，默认走附件教程收益更大的 **Agent 线**，而不是数学 GRPO，也不是旧方案默认的 DPO/ORPO。

### 任务设计

围绕现有检索助手和问诊 / 回答链路构造可程序化判分的环境，而不是教程里的商品询价算术题。`RetrievalAssistantAgent` 的动作空间和 5 轮上限可以直接作为多步环境；问诊与引导则可在「已检索片段 + 系统提示」上做单段或短多轮生成。建议题型：

| 题型 | 本项目中的形态 | 主要考核 |
| --- | --- | --- |
| 多步检索再作答 | 先选 `bm25_search` 或 `vector_search`，结果不足时 `rewrite_query`，再 `finish`，最后按片段作答并引用 | 长程工具规划与依据检索作答 |
| 干扰工具 | 工具列表里混入与当前故障无关的工具或错误设备类型过滤 | 是否选对工具，是否被无关工具带跑 |
| 工具失败恢复 | 某次检索返回空结果或「暂时不可用」，模型应改写查询、换路或如实报知识库未覆盖，而不是编造 | 失败恢复 |
| 引导 JSON / 拒答 / 冲突引用 | 在 SFT 同类题上做组采样，用程序规则打分 | 格式与安全约束在采样下是否仍稳 |

### 筛题（对应教程第 5 章）

不要用单次贪心解码的对错来建训练池。筛题必须复刻训练时的采样条件（温度、最大长度、是否多轮、工具集合），对每道候选题多次生成（教程用 4 次仅作方法参考，本项目次数以显存和稳定性重测后写入配置）。只保留多次尝试中既有成功也有失败的题目。全对或全错的组在训练时相对优势为零或很弱，应当跳过，不要硬训。

训练池必须与冻结评测包去重。池子过小时滚动扩容，而不是在十几道题上反复打转。筛题脚本应支持中断续跑。

### 奖励（必须程序化）

本仓库和附件教程都没有把 LLM 当作裁判。奖励由明确规则相加，再在组内做标准化。建议分量（权重需在评测包上标定，下文数字只表示「对错为主、格式为辅」这一方向，不是已经测过的最佳权重）：

- **任务成功**（主项）：引导 JSON 可按 schema 解析且选项不超出检索片段；问诊 / 检索回答的关键结论能在给定来源中找到；冲突题遵守 `SOURCE_PRIORITY`；检索助手选对了应选工具或在失败后采取了允许的恢复动作。
- **格式**：引用格式、JSON 字段完整、拒答与 `REPAIR_IRRELEVANT_REPLY` 原文一致。
- **依据检索**：出现片段中没有的配件、价格、步骤或安全结论，记为违规并扣分。
- **可选长度惩罚**：超过预设生成长度的轨迹扣分，避免无意义加长。

分别记录各奖励分量，避免总分掩盖「格式变好但开始编造配件」之类的劣化。若一组内所有轨迹奖励完全相同，跳过该步更新。用 KL 相关约束限制偏离 SFT 参考策略的程度，并监控有效组比例；有效组过低时先扩池或改筛题，而不是加大学习率硬训。

### 训练约束

- 每题采样组大小按显存决定；多轮轨迹比单段生成更吃显存，不要照抄教程数学线的组大小。
- **只对模型自己生成的 token 计算损失**，工具返回文本不当作预测目标。
- **不要在同一批里对长短不一的多轮轨迹做左填充混跑**；附件教程发现填充 token 会污染较短任务，应逐条生成或按长度分桶且禁用有害的左填充。
- 温度等生成设置与筛题保持一致。问诊 / 回答类任务的现网温度为 0.5，检索决策现网为 0.1；若 GRPO 为增加组内差异而提高采样温度，必须在筛题时使用同一温度，并在评测时另行报告解码设置。

若程序化奖励或 Agent 环境尚未就绪，可以暂用 DPO/ORPO 作为备选（见「可选支线」），但一旦奖励可跑，应以本阶段为默认强化学习。

## 阶段三：OPD（有条件）

GRPO 的奖励是序列级的，信号较稀疏。OPD 用教师在各生成位置上的概率分布或逐 token 信号，给学生更细的目标。对本项目，教师固定为云端 `qwen-plus`，学生是 SFT 或 GRPO 之后的本地 7B，二者不是同一套权重，理论上比教程里的同源自蒸馏更有机会出现差距。尽管如此，仍必须先做可行性检查，不能默认「一定还要再蒸一次」。

### 必须遵守的教训

- **不要做把最终答案塞进教师提示的自蒸馏。** 附件教程实验 A 用同一模型既当教师又当学生，并在教师侧提供标准答案，结果能力明显崩溃（教程记录 MATH-500 从 47.5% 降到 2.5%，仅属该实验）。教师提示只给现网系统提示、用户问题和检索片段，让教师自己写出过程。
- **先测师生差距。** 在同一批题上比较教师与学生的输出分布或程序化得分。若差异已经很小，再换散度（反向 KL、前向 KL、JSD）也往往没有新信号，应停在 SFT + GRPO。
- 学习率从低处试，并监控格式指标（JSON 合法率、拒答原文、引用格式）。格式崩了就停。
- OPD 不是上线前的必经阶段，也不是用来替代 SFT 或 GRPO 的捷径。

## 可选支线

### Domain CPT

可选，不是默认第一阶段。若手册 / OBD / 脱敏结案文本量足够，可以在基座上做小学习率继续预训练，降低术语生僻度，但必须与 SFT 分开跑、分开存盘。过拟合会背诵件号或车牌，需要用探针集检查。CPT 之后仍然必须进入 SFT，再考虑 GRPO。真实 token 量待用脚本统计，本文不编造语料规模。

### DPO / ORPO

仅当程序化奖励还没准备好，或已经有明确的技师采纳 / 改写对时作为备选。chosen 应是技师最终采纳的话术或改后的建议项目名称；rejected 是模型原稿或把「条件更换」说成已确认并写出金额的错误叙述。只比较项目名称，不把规则引擎算出的价格当作语言模型该学的内容。样本不足时可用 ORPO 或小学习率短训。严禁跨店混偏好。门禁与 SFT 相同：JSON 合法率不下降，「只依据检索」违规率不升，私有实体探针不泄漏。

### Reranker 并行微调

冻结 embedding。用 FlagEmbedding 或 transformers，从现网同款 `BAAI/bge-reranker-v2-m3` 出发，做成对交叉熵或 Listwise。负例用错车型、错件号或无关手册（例如刹车问句对 P0420 条目）。导出后把权重目录放到 `embedding_server.py` 的 `_RERANKER_LOCAL_CANDIDATES` 最前面，接口 `/v1/rerank` 不变，加载器仍走 FlagReranker（`normalize=True`，输出 0~1）。

**不要把 Qwen3-Reranker-0.6B 或其它 CausalLM Yes/No 权重直接塞进该列表。** 现网加载器是 FlagReranker，代码已写明禁止再走旧的 Qwen3 CausalLM Yes/No 路径，否则会误打 BGE 分数。若要换架构，必须先改加载器再换模型。微调或换精排后，应重跑 `calibrate_thresholds.py`：配置注释写明质量阀门仍按旧版 Qwen 精排标定、尚未按 bge-reranker 重标。验收用固定 query 集上的排序指标（如 nDCG@10 / MRR）相对原版对比，标注集规模待补充。

## 评测

评测由程序完成，不引入额外的 LLM 裁判。MATH-500 不是本产品的验收指标；若引用附件教程中的 12.5%→45%→47.5% 或 Agent 46.7%→86.7% 等数字，只用于说明教程方法曾经怎么被验证，不得写成本项目的基线或目标。

### 评测包

先冻结一份与训练集去重的汽修 held-out 黄金集，再填任何数字。建议覆盖：引导 JSON、检索问答（含引用和冲突）、车主问诊三段、拒答、工具选择 / 失败恢复。具体条数在建包时确定并写回本文，不在这里虚构已经存在的规模。

对比对象（基于现网接线的技术对照，不是已记录的 POC）：

1. 未微调的本地 `Qwen2.5-7B-Instruct`（`CHAT_LLM_MODE=local`，服务名仍为基座名）；
2. SFT 检查点；
3. GRPO 检查点（若做了 OPD，再单列 OPD 检查点）；
4. 云端 `qwen-plus`（`CHAT_LLM_MODE=cloud`，验收基线）。

### 程序化指标

| 门禁项 | 定义方式 | 通过线 | 现状 |
| --- | --- | --- | --- |
| 引导 JSON 合法率 | 解析 `options` / `status` 等字段成功占比；题目约定的必要选项是否出现 | 相对未微调 7B 改善，并与 `qwen-plus` 对照；绝对通过线待评测包建成后定 | 待补充 |
| 依据检索违规率 | 回答中出现给定片段没有的配件、价格或步骤，记一次违规 | 不差于基线 `qwen-plus`，且不差于上一阶段检查点 | 待补充 |
| 引用来源与冲突 | 须注明出处；冲突时不得只采用低优先级结论 | 同上 | 可用 `test_rag_source_cite` 作回归，但仍需样本集 |
| 车主问诊结构 | 须同时有症状理解、建议项目、是否预约，且不编造目录价格 | 同上 | 可用现有文案单测作回归，但仍需样本集 |
| 闲聊拦截 | 应拒则拒，且文案与当时 `REPAIR_IRRELEVANT_REPLY` 一致 | 不低于现网阀门 + 对应模型组合 | 有单元测试可复用 |
| 工具选择 / 恢复 | 多步检索是否选对工具，失败后是否改写、换路或如实报未覆盖 | 相对 SFT 改善 | 待补充；评测时应逐条生成，避免混批填充干扰 |
| 稳定性（可选 pass³） | 同一题独立执行 3 次，三次都通过才计为通过 | 用于观察采样稳定性，不替代单次正确率 | 待补充 |
| 端到端有用率 | 技师盲评 A/B（`qwen-plus` vs 本地检查点） | 本地胜出或打平的比例待组织后填写 | 待补充 |
| 检索侧（若动 rerank） | nDCG@10 / 人工 top3 相关 | ≥ 精排微调前 | 待补充标注；动精排后须重标定阈值 |
| 延迟与成本 | P95 首 token 与整答、调用费用 | 门店可接受的 SLA 待补充 | 本文不编造现网延迟或费用 |

解码设置需要在评测报告里写明。关键题应多次独立运行，避免把单次偶然生成当成阶段结论。独立评测变差时，优先检查训练池污染、奖励漏洞和 KL 漂移，而不是继续加步数。

## 接回与上线核对

环境变量写在 `backend/.env`，与 `backend/.env.example` 对齐，不要改仓库根目录下并不存在的业务 `.env` 来切换模型。

1. 合并 LoRA 后用 vLLM 在 `http://127.0.0.1:8001/v1` 拉起，例如：

```bash
python -m vllm.entrypoints.openai.api_server \
  --model saves/car-repair-7b-merged \
  --served-model-name car-repair-7b \
  --port 8001
```

2. 用 curl 打 `/v1/chat/completions`，带上现网某条引导或问诊系统提示做冒烟。
3. 修改 `backend/.env`：`CHAT_LLM_MODE=local`；`CHAT_LOCAL_BASE_URL=http://127.0.0.1:8001/v1`；`CHAT_LOCAL_API_KEY=dummy`；`CHAT_LOCAL_MODEL=car-repair-7b`。**`CHAT_LOCAL_MODEL` 必须等于 vLLM 的 `--served-model-name`。** 不要改 `DEEPSEEK_*` 来接本地模型，除非临时把模式设为 `deepseek` 做兼容对照。本地超时地板为 `CHAT_LOCAL_TIMEOUT_FLOOR`（默认 30 秒）。
4. 保持检索不动：8010 仍为 bge-m3 +（可选新的）bge-reranker；`VECTOR_DIM=1024` 不变。
5. 在 `backend/` 下跑 pytest（至少 `test_chat_llm_mode.py`、`test_phase*.py`、`test_auth_scope.py`、`test_rag_source_cite.py`）；手动跑智能问答 SSE、`guided_repair_chat`、知识抽取、MCP `search_knowledge` / `draft_quote`。
6. 灰度：按门店或按用户开关切 `CHAT_LLM_MODE` / `CHAT_LOCAL_*`。出问题把 `CHAT_LLM_MODE` 改回 `cloud`（需已配置 `CHAT_CLOUD_API_KEY` 或 `DASHSCOPE_API_KEY`）并重启业务进程。回滚是切回云端，不是切到 DeepSeek。
7. 若曾换 embedding：给新 embedding 列灌数 → 在 `backend/` 下执行 `python scripts/calibrate_thresholds.py` → 回填 `backend/.env` 阈值 → 再切流量。回滚是切回旧列或备份，不是集合别名。

## 风险与回滚

| 风险 | 表现 | 缓解 | 回滚 |
| --- | --- | --- | --- |
| 幻觉零件 / 价格 | 案例没有的配件或目录金额出现在回答里 | SFT / GRPO 都用「只依据检索」约束；问诊 / 回答温度保持 0.5（与现网一致）；报价仍以规则引擎为准 | 切回 `CHAT_LLM_MODE=cloud` |
| JSON 损坏 | 引导 `options` 解析失败 | 提高 JSON 样本占比；解码可加约束或重试；GRPO 把可解析性写入奖励 | 该路由临时回云 |
| 跨店隐私泄漏 | 模型吐出他店案例细节 | 按 store 分片训练或加店前缀控制；脱敏；探针集 | 下线该 adapter |
| 误换 embedding | 召回分数整体漂移 | 流程门禁禁止无标定发布 | 切回旧 embedding 列或备份，而不是集合别名 |
| 误换精排架构 | 把 Qwen3-Reranker 权重塞进 bge 的 FlagReranker 加载路径，分数失真 | 只替换同架构 bge-reranker 权重；换架构先改加载器 | 恢复 `_RERANKER_LOCAL_CANDIDATES` 原目录 |
| CPT 指令退化 | 不会按系统提示拒答 | CPT 后必须 SFT；保留通用指令混合 | 弃用 CPT ckpt，从基座重做 SFT |
| 拒答文案锁死工业举例 | 现网 `REPAIR_IRRELEVANT_REPLY` 仍是注塑机 / 空压机 / CNC，SFT 照抄会把举例带进模型 | 若要汽修举例，先改代码文案再刷新样本 | 下线该 adapter，或改回与现网原文一致的拒答样本 |
| 拒绝采样教材偏易 | 学生只会做已经会的题 | SFT 主教材用参考轨迹和教师 `qwen-plus` 合格输出 | 丢弃该批 RS 数据，按质量门禁重建 |
| GRPO 无组内差异 | 损失不动或只学到固定套话 | 按训练采样条件重新筛题；跳过全对 / 全错组；扩池 | 回到 SFT 检查点 |
| 混批左填充污染 | 短轨迹被 pad token 带偏 | 逐条生成或按长度分桶，禁用有害左填充 | 用未污染设置重训该阶段 |
| OPD 教师提示不当 | 学生格式或能力明显变差 | 禁止向教师提供最终答案；先测分布差距；低学习率并监控格式 | 弃用 OPD ckpt，回到 SFT 或 GRPO |
| 把教程指标当成验收 | 用 MATH-500 或教程百分比决定是否上线 | 只用本项目冻结汽修集和程序化指标 | 重新按本文评测章验收 |

## 分阶段计划

以下是可执行的工作顺序，不是已经完成的进度。数据量和指标在对应周完成后回填。

- [ ] W1 环境与数据：本机加载未微调 `Qwen2.5-7B-Instruct` 并完成一次现网提示词推理冒烟；从 `COMPLETED` / `ARCHIVED` 及已发布工单知识、手册 / OBD、已发布 FAQ 导出、脱敏、按 store 分片；统计 token。设计 `training_events` 或打通 `consult_*` 落库，但不要把尚未落库的聊天写进训练集。
- [ ] W2 冻结评测包：与训练集去重；覆盖引导、引用 / 冲突问答、问诊、拒答、工具选择。跑通未微调本地 7B 和云端 `qwen-plus` 的程序化基线，把本文「待补充」填成首版数字。
- [ ] W3 SFT：按质量门禁构建参考轨迹（含教师 `qwen-plus` 合格输出）；只对助手 token 算损失；按显存选择 LoRA / QLoRA。通过 JSON、引用、拒答门禁后再进入强化学习。
- [ ] W4 Agent GRPO：按训练采样条件筛出有组内差异的任务；程序化奖励；只在模型生成 token 上计算损失；逐条或多长度分桶生成。有效组过低则扩池，而不是盲目加步数。
- [ ] W5 有条件的 OPD、接回与可选精排：先测 `qwen-plus` 与学生的差距，差距不足则跳过 OPD。vLLM 的 `--served-model-name` 与 `CHAT_LOCAL_MODEL` 对齐后，`CHAT_LLM_MODE=local` 灰度一店，保留一键切回 `cloud`。可选在 `bge-reranker-v2-m3` 上微调并重标定阈值；embedding 仍冻结。组织技师盲评并复盘。
