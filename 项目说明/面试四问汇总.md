> 代码底账已核对：`qa_graph.py` / `robot_graph.py` / `work_order_importer.py` / `retrieval_agent.py` / `retrieval_flow.py` / `config.py:93-99`

## Q1：你的维修项目中有几个 agent？

**30 秒答案：报"自主性"，不报裸数字。**

> "严格意义 2 个——我的判断标准是'**模型在循环里自主决定下一步做什么**'。往下是三类没有自主性的东西：**3 张 LangGraph 图**是代码编排的确定性流程——问答图、钉钉机器人图、工单导入图；**注册给 Agent 的 6 个检索动作**是工具，模型按名字调；**8 个 LLM 技能**是代码直接调用的单次结构化生成——把模型当函数用。整套架构一句话：**工作流为主，智能体为辅，该用 agent 的地方才用 agent。**"

**底账表（按"谁在决策"一条轴）：**

| 概念 | 谁决策 | 特征 | 组件 |
|---|---|---|---|
| **Agent** | 模型 | 循环里自主选下一步动作 | 2：ReAct 检索代理、专家维修代理 |
| **图（工作流）** | 代码 | 流程确定，模型在节点里"填空" | 3：问答图、钉钉机器人图、工单导入图 |
| **工具** | 模型选 | 函数被模型按名字调用 | 6 个动作：向量检索、BM25、条件筛选、关联查询、查询改写、结束 |
| **技能** | 代码调 | 一次调用出结构化结果，无循环 | 8：工单理解、故障拆解、引导维修、知识抽取、去重判定、关键词提取、手册结构化、会话摘要 |

**关键记忆点：工具和技能是一对镜像**——工具是"模型调函数"，技能是"代码调模型"。这个对称结构讲出来，面试官立刻知道你脑子里有张地图，不是在背分类。

**追问"为什么不多拆一点 agent"：**

> "Agent 每一轮决策都要过 LLM，是系统里最贵的执行单元。我们只在决策空间真正开放的地方给自主性：检索代理要判断'结果不够要不要改写重试'，专家代理要判断'用户反馈后往哪个方向推进'。像工单导入这种流程，步骤是确定的，做成 agent 纯属浪费。**知道什么时候不用 agent，和知道什么时候用，是同一件事的两面。**"

**追问"你这 8 个模块为什么不做成工具"：**

> "工具是给模型调的——模型按名字选。这 8 个技能是业务代码在确定时机直接调用的：工单完成时调知识抽取、入库前调去重判定。调用时机由代码决定，不需要模型来选，做成工具反而多绕一层。真正的工具层是注册给 ReAct 代理的那 6 个检索动作。"

**被逼要数字时**："严格按'模型自主决策'算 agent 是 2 个；连图带技能算上，十来个 LLM 组件。文件命名带 agent 的更多，但命名归命名，标准归标准。"

**诚实边界**：AnswerGenerator 文件头注释明确写"功能工具模块，非 Agent"——基于检索案例生成回答，被追问时别把它算进 agent 数。retrieval_flow.py 是公共检索编排层（四入口共用），也不是 agent，但它是解耦的关键证据，讲架构必须提。

## Q2：2 个真正的 agent 会不会无法完成工作？

**30 秒答案：把质疑反转成架构取舍展示。**

> "严格说是两个，但这个数字本身不是重点——**系统大部分请求根本不经过任何 agent**。我们的架构是'工作流为主、智能体为辅'：三张 LangGraph 图负责确定性编排，让系统'能跑'；两个 Agent 负责自主决策，让系统'聪明'。设计上就是管道优先：标准检索管道质量达标就直接出结果，不达标才升级到 ReAct 深度检索。所以那两个 agent 更像是救援通道，不是主干道。"

**追问"这不就是个工作流引擎吗"：**

> "看怎么定义多智能体。如果标准是'有多个自主决策体在协作'，我们有——ReAct 代理在工具循环里自主决策，专家代理做多轮引导。如果标准是'每个功能都套一层 agent 壳'，那确实不是，我也不认为是好设计。多智能体的价值在分工，不在数量。"

**警惕衍生追问："那你的项目跟大模型关联是不是不强？"**

> "强，但强在**模型是基础设施**而不是显性卖点。一次完全不碰 agent 的请求，最少经过 3~4 次模型调用：意图分类、Embedding 编码、Reranker 精排、回答生成。我们最重的资产——自动沉淀的知识库——本身就是 DeepSeek 从工单里抽取造出来的。我刻意收敛的是决策型 agent 的数量：确定性流程走图和管道，开放性决策才出动 agent。**知道什么时候不用 LLM 决策，和知道什么时候用，是同一件事的两面。**"

**一条 SV0436 查询的走查底牌**（细节追问用）：

1. 意图路由判定走故障子图（不经过 agent）
2. 复合故障预检，单故障零 LLM 过（不经过 agent）
3. 双库四路召回 → RRF → 粗筛 → 严格过滤 → 精排 → 错误码置顶（不经过 agent）
4. 到这一步系统已给出答案——全程没有 agent 参与
5. 只有质量不达标才升级 ReAct；用户要深度分析才进专家代理

## Q3：如何判断质量是否达标？

**代码实况（`retrieval_flow.py:359-375`，三个入口共用一个函数）：**

```
达标条件：结果数 ≥ 3 且（高分条数 ≥ 2 或 最高分 ≥ 0.7）
其中"高分"= 单条向量分 ≥ 0.6
```

对应配置（`config.py:98-99`）：
- `AGENT_QUALITY_HIGH_SCORE = 0.6` —— "高分"单条线
- `AGENT_QUALITY_TARGET_SCORE = 0.7` —— 最高分达标线

**30 秒答案：**

> "质量评估是**纯规则判定，零模型调用**——这一步每条查询都要过，用 LLM 评估等于把管道优先省下的成本又花出去。判定委托给公共阀门函数，三个入口（ReAct、专家救援、公共编排层）复用同一套规则：**结果数不少于 3 条，且要么有至少 2 条高分（0.6 以上），要么最高分冲到 0.7**。达标直接出结果，不达标才升级 ReAct 让模型自主改写重试。"

**追问"评估错了怎么办"：**

> "两个方向都有兜底：ReAct 循环有最大迭代轮数上限，到最后一轮强制算达标，防死循环；误放行结果偏弱时，下游生成侧还有把关——模型生成时对低置信结果降低引用权重。质检不是唯一防线，是分级防线的第一级。"

**追问"阈值怎么定的"：**

> "跑分数分布标定的，不是拍的。粗筛那条 0.45 的线，实测无关输入向量分不超过 0.353、正常故障查询在 0.571 以上，取中间。质量阀门的 0.6/0.7 也是同样的方法。"

**注意（重要修正）**：质量阀门**不看错误码命中**——错误码相关的是另一个机制（过滤阶段的错误码精确命中置顶），别在面试里说"质检还查错误码"，代码里 `evaluate_retrieval_quality` 只查条数和分数。

**加分细节（可讲可不讲）**：ReAct 代理里还有一道"强制混合检索"预检——第一轮先双路并发跑完，达标就直接进 RRF 融合、跳过 LLM 决策循环。这是防"第一轮选单路、恰好达标就早停、混合检索名存实亡"的补丁，能讲出这个说明你真调试过。

## Q4：过线的指标是什么？

**先分清：0.45 是粗筛线，不是质量线——这是两套阈值，混了就露馅。**

| 阈值 | 值 | 用在哪 | 代码位置 |
|---|:---:|---|---|
| RETRIEVAL_COARSE_THRESHOLD | **0.45** | 粗筛放行 + 钉钉维修意图判定（统一口径） | config.py:93 |
| AGENT_QUALITY_HIGH_SCORE | **0.6** | 质量阀门："高分"单条线 | config.py:98 |
| AGENT_QUALITY_TARGET_SCORE | **0.7** | 质量阀门：最高分达标线 | config.py:99 |
| RETRIEVAL_VECTOR_THRESHOLD | 0.3 | 单路向量检索 | config.py:95 |
| REPAIR_INTENT_RELEVANCE_THRESHOLD | 0.4 | 维修意图最终判定 | retrieval_flow.py:384 |
| SEMANTIC_RESCUE_THRESHOLD | 0.6 | 语义兜底：保英文日志→中文手册跨语言命中 | config.py:94 |
| DEDUP_LLM_THRESHOLD | 0.55 | 去重：触发 LLM 判定 | config.py:97 |
| BM25-only 降级线 | 0.15 | 推理服务挂掉时的放行线 | retrieval_flow.py:228 |

**30 秒答案：**

> "核心是 0.45 这条粗筛线，用在 RRF 融合后的向量分放行，同时作为钉钉维修意图判定的口径——两处统一避免策略漂移。定 0.45 是跑分数分布标定的：实测无关输入的向量分不超过 0.35，正常故障查询在 0.57 以上，0.45 取中间。质量阀门是另一套：0.6 的高分线和 0.7 的最高分线，配合最少 3 条结果数。另外有分层阈值——0.6 的语义兜底线保英文日志跨语言命中，0.55 触发 LLM 去重，0.15 是推理服务挂掉 BM25-only 降级时的放行线。"

**一句话心法**：把"一条 0.45"讲成"一套分层阈值"——每条线都有明确的触发场景和标定依据，这是数据驱动调参的证据链。

## 四问串讲逻辑（总纲）

这四个问题其实是**一条线**：

> **Q1 报结构（自主性一条轴：Agent/图/工具/技能）→ Q2 讲取舍（agent 是救援不是主干）→ Q3 讲判据（救援的触发规则）→ Q4 讲标定（规则的数字怎么来的）。**

面试官问这四问，本质在考同一件事：**你知不知道 agent 的边界在哪。** 答案的核心句式是——"确定性的事交给图（便宜、可控），开放性的事才交给 agent（贵、灵活）；而判断该走哪边的规则本身，必须是零成本的。"

## 术语口径（防混用）

| 术语 | 什么时候用 | 什么时候不用 |
|---|---|---|
| Agent | 模型在循环里自主决策的（2 个） | 别叫给单次调用的技能 |
| 图 / 工作流 | LangGraph 编排的确定性流程（3 张） | 别说成"agent" |
| 工具 | 注册给 ReAct 的 6 个动作（模型按名字调） | 别套到 8 个技能头上 |
| 技能 | 代码直接调的单次 LLM 结构化生成（8 个） | 别叫"工具"也别叫"agent" |

一句话记住整套口径：**"2 个 Agent 自主决策，3 张图定流程，6 个工具给模型调，8 个技能当函数用。"**
